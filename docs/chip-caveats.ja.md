# 系列ごとの注意点

知らないとつまずく振る舞いをまとめます。公式のエラッタに無いものが中心で、どれもベンチで実際に起きたことです。エラッタにあるものも、使い方に響くものは載せます（errata の id は ch32-device-data の `curated/errata.csv` のもの）。

項目ごとに、次の 3 つを書きます。

- **起きること**：何が起きたか。
- **コア**：このコアが何をしているか。Arduino の API だけを使うスケッチなら、多くは気にしなくて済みます。
- **自分で書くとき**：レジスタを直接触るとき、割り込みの処理を自分で書くとき、WCH の EVT のコードを持ち込むときに、要ること。

日付は確かめた日で、詳しい経緯はコードのコメントにあります（ファイル名を添えます）。まだ原因が分かっていないものは「調査中」と書きます。

## どの系列にも共通（QingKe）

| 起きること | コア | 自分で書くとき |
|---|---|---|
| V3B / V3F / V4 系のコアでは、スケッチは U モードで走る。mstatus を読み書きすると不正命令（mcause 2）になり、トラップの処理で止まる | `interrupts()` / `noInterrupts()` と、コアの内部の `ch32rv_irq_save()` / `ch32rv_irq_restore()` は、CSR 0x800（gintenr）を使う（`internal/ch32rv_irq.h`） | 割り込みを止めるときに `csrci mstatus, 8` などを書かない。`noInterrupts()` を使うか、gintenr（0x800）を使う。V2 系と V103（V3A）は M モードで、mstatus を使う |
| V103 を除く系列は、割り込みに入るときにハードウェアがレジスタを退避する（HPE） | 割り込みの処理は `CH32RV_INTERRUPT`（WCH-Interrupt-fast）で作る（`internal/ch32rv_interrupt.h`） | 自分で割り込みの処理を書くときは、`CH32RV_INTERRUPT` を付けるか、`attachInterrupt()` などのコアの入口を使う。ふつうの `interrupt` 属性でも動くが、退避が二重になって遅い |
| 休止（standby）から起きたときのリセットの印が、系列で違う。V307 は SBF、V203 は WUF だけ、V103 は何も残さない | `CH32RV.resetReason()` が `CH32RV_RESET_DEEPSLEEP` に読み替える（`ch32rv_power.c`） | RCC_RSTSCKR を自分で読んで起きた理由を決めない。`resetReason()` を使う |
| リセットの印（RCC_RSTSCKR）は、RMVF を書くまで消えない。いちばん古いリセットのまま残る | `resetReason()` は最初の呼び出しで読み、印を消す | UIAPduino のブートローダーは、NRST の印が残っているときだけ留まる。setup() で `resetReason()` を呼ぶスケッチは、その印を消す（[uiapduino-hid-upload.ja.md](uiapduino-hid-upload.ja.md)） |

## コアが補っていること（まね・代わりの処理）

石に無い機能や、石のくせを、コアがソフトで補っている所です。Arduino の API はほかの環境と同じに見えますが、速さや、電源を切ったときの残り方などが違います。

| 機能 | 系列 | 石の事情 | コアの処理 | 違いと費用 |
|---|---|---|---|---|
| `OUTPUT_OPENDRAIN` | X035 / X033 | GPIO にオープンドレインが無い | High は浮いた入力に、Low はプッシュプルの 0 に、端子のモードを切り替える（`wiring_digital.c`、`ch32rv_gpio_od_write()`） | 1 回の切り替えで設定のレジスタを読み書きするので、本物より遅い。`digitalWrite()` 1 回が、プッシュプルの 54 サイクルに対して 74 サイクル（48 MHz で 1.1 µs と 1.5 µs、2026-11-22。本物のオープンドレインの V205 はどちらも 11 サイクル。どれも端子が定数で関数が展開された形の値で、関数として呼ぶと X035 のプッシュプルは 134 サイクル。大半はフラッシュの待ち 3 の命令の取り込み）。SoftWire・1-Wire の上限が下がる。ハードウェアの I2C は石が自動でオープンドレインにするので変わらない |
| `UsartSPI` の MSBFIRST | 全系列 | USART は下位ビットから送る形しか無い | 1 バイトごとにビットを並べ替える（`HardwareSerialSync.cpp`） | 1 バイトごとに数命令ぶん遅い |
| `rgbLedWrite()` | WS2812 のブロック（ARGB）の端子以外 | WS2812 を出す周辺が無い（V4x7 の PA15、X3x5 の PA15 / PD3 / PD4 だけにある） | 割り込みを止めて、ソフトでビットを出す（`ch32rv_rgb_led.c`） | LED 1 個（24 ビット）につき約 30 µs、割り込みが止まる。その間の割り込みは遅れる |
| `analogReference()` | 全系列 | 基準の電圧を選べない（ADC はいつもアナログの電源を基準にする） | 呼んでも何もしない（`wiring_analog.c`） | 読み値はいつも電源の電圧に対する比 |
| `analogReadMilliVolts()` | 全系列（M030 を除く） | — | 呼ぶたびに内部の基準（Vrefint）で電源の電圧を測り、そこから mV に直す | M030 は Vrefint が無く、電源を 3300 mV と仮定する。初期のロットの X035 は IN15（Vrefint）が狂う |
| `ch32rv_random()` | 乱数の周辺（RNG）が無い系列（V30x・V4x7・H41x 以外） | 乱数の周辺が無い | 石の ID と SysTick の値を混ぜてソフトで作る（`ch32rv_random.c`） | 暗号には使えない（知っている人には予想できる）。本物が要るときは `ch32rv_rng_read()`（無い系列では false） |
| `CH32RV.getUniqueId()` | 全系列 | 96 ビットの ID のうち、上の 32 ビット（UNIID3）は石ごとに違わない（errata `esig-uniid3-not-unique`） | 下の 64 ビットだけを使う | ID は 64 ビット |
| RTC のバックアップのレジスタ（`ch32rv_backup_*()`） | H41x、X305 / X315 | バックアップのデータのレジスタ（BKP）が無い | RAM の `.noinit` の領域に置く（`internal/ch32rv_rtc.h`） | RAM の電源が残るリセットでは残るが、電源を切ると消える（VBAT でも残らない）。RTC も 1970 年から数え直す |
| `lightSleep()` / `deepSleep()` と IWDG | 全系列 | 動いている IWDG は止められない | 休止を IWDG の周期より短く区切り、間で IWDG を叩く（`internal/ch32rv_power.h`） | IWDG を使うと、休止の途中で何度も起きる（そのぶん電流が増える） |
| 休止の間の `millis()` | 全系列 | 休止の間は SysTick が止まる | 自動起床（AWU）が測った時間を足し戻す。端子で起きて長さが分からないときは足さず、`ch32rv_time_domain` を進める | 端子で起きると、その休止の分だけ `millis()` が遅れる |
| `attachInterrupt()` | 全系列 | EXTI の線は端子の番号ごとに 1 本（3 番の線は PA3・PB3・PC3 のどれか 1 つ） | 後から付けた端子に置き換える（`wiring_interrupts.c`） | PA3 と PB3 を同時に割り込みにできない。エラーにはならず、前の方が黙って外れる |
| 周辺のクロックを入れた直後の書き込み | H41x | V5F は周辺のバスより 4 倍速く、書き込みが遅れて効く | RCC を読み返してから書く。MOE などは効くまで読み直す | コアの中の数命令。自分でレジスタを書くときは同じことが要る（下の H41x の節） |

## デバッガ（WCH-LinkE / WCH-Link）で接続するとき

| 起きること | コア・ch32rv | 自分で書くとき |
|---|---|---|
| 走っている石に接続すると、レジスタが 1 つ壊れる。V103（Link CH549）は s1 を石の ID で、V205（LinkE fw 2.22）は s0 を 0xE000D004 で上書きした。H417 の V3F は、およそ 2 回に 1 回 a0 が 0 になった。次の読み書きで、境界の例外やアクセス違反になる | ch32rv は、接続のあとに石を再起動して避ける（H417 は 1c45634 以降） | 動いているスケッチに接続して値を何度も読む測り方は、壊れる前提で考える。リセットのたびに 1 回だけ読む。接続した直後にだけ起きる説明のつかない落ち方は、まずこれを疑う |
| 接続で、石のクロックを組み替える。H417 では HSE が切られ、USB SS のリンクが張り直しになった | ch32rv の discovery は LinkE の先の石に接続しない | クロックや USB の状態を見る試験では、接続してから始める。USB SS を使うなら、端末は SS を始める前につなぐ |
| H417 で UHSIF が動いたままだと、LinkE での書き込みが「読み返しが合わない」で失敗する。CPU を止めても DMA は止まらず、書き込み用のローダーを上書きする | — | 書き込む前に、スケッチ側で UHSIF を止める（[h417-uhsif.ja.md](h417-uhsif.ja.md)） |

## CH32H41x（H417 / H416 / H415）

コアが 2 つあり、周辺のバスより CPU がずっと速い、ほかの系列と前提が違う石です。CPU Core のメニューの既定は V5F で、V3F が起動して V5F を起こします。

| 起きること | コア | 自分で書くとき |
|---|---|---|
| V5F（400 MHz）は周辺のバス（100 MHz）より 4 倍速く、書き込みが遅れて効く。クロックを入れた直後の最初の書き込みが消えた（WWDG_CFGR が既定値のまま、リセット直後の端子の最初の出力が出ない、2026-11-15） | クロックを入れたあと、RCC のレジスタを読み返してから次を書く（`internal/ch32rv_registers.h`） | 周辺のクロックを入れたら、RCC のレジスタを 1 回読み返してから、その周辺に書く |
| 書いた直後に読むと、まだ古い値が返ることがある。TIM1 の BDTR に MOE を書いた直後の読み返しが、まだ 0 だった（2026-11-21） | `CH32RVComplementaryPwm::resume()` は最大 64 回読み直す | 書いた値をすぐ読んで判定しない。効くまで読み直すか、読み返しで書き込みの完了を待つ |
| RTC の RTCSEL を、バックアップ領域のリセットの直後に書くと消えた（RTCEN だけ立ち、RTC にクロックが無い、2026-11-14） | 項目ごとに読み返してから次を書く（`ch32rv_rtc.c`） | RCC_BDCTLR は 1 項目ずつ書き、読み返して確かめる |
| AFIO のクロックが入っていないと、端子の機能の選択の書き込みが消え、端子が機能無しのまま残る（analogWrite() の端子が High に張り付いた） | 機能を選ぶ前に AFIO のクロックを入れる（`internal/ch32rv_gpio.h`） | AFIO のレジスタを書く前に、AFIO のクロックを入れる |
| RCC_RSTSCKR の場所が 0x28（ほかの系列は 0x24）。0x24 を読むと、リセットの理由が分からない | 系列ごとの場所を使う（`internal/ch32rv_registers.h`） | EVT 以外の系列のコードを持ち込むとき、RSTSCKR の場所を直す |
| V5F が共有 SRAM の同じ語を休みなく回し続けると、V3F がそのバンクから締め出され、チップ全体が止まる | コアの V3F の待ちは WFI（イベント待ち）で待つ（`crt0_ch32.S`） | 2 つのコアの間の待ちで、共有 SRAM のフラグを休みなく回さない。IPC か HSEM を使う |
| picolibc の malloc には、コアをまたぐ鍵が無い。2 つのコアが同時に確保すると、ヒープが壊れた（2026-11-19） | V5F のビルドでは、malloc / free などを HSEM の鍵で包む（`ch32rv_heap_lock.c`） | 2 つのコアで動的確保を使うときは、コアの malloc を使う（自分のアロケーターを持ち込まない） |
| I2C の入力クロックは HCLK そのもので分周できない。FREQ の欄の上限（60 MHz）を超える | FREQ を 60 で頭打ちにする | I2C の速さは、規格の上限より遅めに出ることがある（[peripheral-support.ja.md](peripheral-support.ja.md)） |
| **調査中**：V5F で USART の割り込みが続くと、V5F が固まる。「走っている」状態のまま、デバッガでも止められない。短いコマンドとその返事を続けると、数百〜数千回で起きる。V3F では 15000 回、DMSeq のコンソールでは 10000 回、起きなかった（2026-11-21） | まだ対策は無い | V5F で Serial を多く使うなら、CPU Core を V3F にするか、コンソールを DMSeq / RTT にする（[debug-output.ja.md](debug-output.ja.md)） |
| 評価ボードの PB8 / PB9 は SWD と兼用。VIO18 は起動時 1.2 V | ボードの定義で扱う | [h417-bench.ja.md](h417-bench.ja.md) |

## CH32X035 / X033

| 起きること | コア | 自分で書くとき |
|---|---|---|
| 48 MHz でフラッシュの待ちが 2 未満だと、命令を読み違えて setup() の前に止まる | クロックを上げる前に待ちを設定する（`wiring_time.c`） | クロックを自分で変えるときは、待ちを先に増やす |
| LSI が 46.9 kHz（ほかの系列は 128 kHz）。休止の時間の較正の窓が長く、起動して最初の lightSleep() が、頼んだより約 100 ms 長かった（200 ms が 317 ms、2026-11-05） | 較正の窓を X035 用に短くした（`ch32rv_power.c`） | 最初の 1 回の休止は、少し長くなることがある |
| 同期モードの USART は、1 回も送らないと TC が立たない。end() が送り終わりを待って返らなかった（2026-11-19） | 同期モードの end() は送り終わりを待たない（`HardwareSerial.cpp`） | TC を待つ前に、1 回は送ったかを確かめる |
| PA16〜PA23 は、ほかの端子のように BSHR では動かせない（BSXR / BCR を使う） | `digitalWrite()` などは系列ごとのレジスタを使う | 端子を直接動かすコードは、PA16 以降を別に扱う |
| GPIO にオープンドレインの出力が無い。出力モードの CNF = 01 は、プッシュプルと同じく High を出す（errata `x035-no-gpio-open-drain`、PA0 / PA5 / PB3 / PB12 / PC14 で確かめた、2026-09-22）。手放せるのは AF のオープンドレイン（CNF = 11）だけで、そのときは周辺が端子を持つ | `OUTPUT_OPENDRAIN` は、Low をプッシュプルの 0、High を浮いた入力に切り替えてまねる（`wiring_digital.c`）。SoftWire も同じ | レジスタで CNF = 01 を書いてオープンドレインのつもりにしない。I2C や 1-Wire の線を自分で動かすときは、入力と Low の出力を切り替える |
| PC16 / PC17 は USB の PHY の端子で、AFIO_CTLR の USB_PHY_V33（リセット値 0x45 に含まれる）が立っていると、オープンドレインが手放さずに High を出す。I2C の相手が ACK できず、Wire の route 2 / 4 はいつもアドレスの NACK になった（errata `x035-usb-pads-open-drain`、2026-09-22） | どちらかの端子を出力にするとき、USB_PHY_V33 を落とす（`internal/ch32rv_gpio.h`）。USB を始めるときは USB の側が立て直す | PC16 / PC17 を I2C などに使うときは、USB_PHY_V33 を落とす |
| 初期のロット（ロット番号の後ろから 5 桁目が 0）は、ハードウェアの I2C が使えない。I2C1 を有効にすると、SDA が待機中もプッシュプルで High を出す（AF のオープンドレインでもプッシュプルでも同じ）。同じロットは、ADC のチャネル 3・7・11・15 も使えず、IN3・IN7 は前のチャネル（IN2・IN6）の値を返すので、もっともらしく間違う（errata `x035-adc-ch-i2c-unavailable`、2026-11-03） | 石のロットは読めないので、コアは区別しない | 初期のロットの石では、I2C は SoftWire を使う。ADC のチャネル 3・7・11・15 の値を信じない。刻印が読めないときは、IN3 が IN2 と同じ値になるかで見分けられる |
| F8U6 と D8U6 を除く形では、PC10 と PC17、PC11 と PC16 が中でつながっている（errata `x035-pc10-pc17-bonded`） | — | 対になった 2 つの端子を、同時に出力にしない |
| タイマーの更新の直後の最初のカウントで、比較の一致が消えた | `CH32RVPhaseShift` などは、一致が最初のカウントに来ないように、カウンタを 1 つ手前から始める（`CH32RVTimerGroup.cpp`） | 更新（UG）の直後の最初のカウントでの一致を当てにしない |

## CH32V003 / V002 / V004 / V005 / V006 / V007（V00x）

## CH32V103

| 起きること | コア | 自分で書くとき |
|---|---|---|
| USART の語長（CTLR1 の M）は、送受信（TE と RE）を両方止めた書き込みのあとでないと変わらない。アドレスで起きる待ち（RWU）は、UART を有効にした（UE を立てた）書き込みの次でないと立たない（2026-11-21） | 書き込みの順番を合わせた（`HardwareSerialMode.cpp`） | 9 ビットやマルチプロセッサのモードを自分で設定するときは、TE と RE を止めてから M を変え、UE を立てた次の書き込みで RWU を立てる |
| HPE が無い（QingKe V3A）。ベクター表は番地ではなく jump 命令の並び | 割り込みの処理はふつうの `interrupt` 属性で作る | EVT 以外のコードを持ち込むとき、ベクター表の形の違いに注意する |
| U モードを持つが gintenr が無い | スケッチは M モードで走る | 割り込みを止めるときは mstatus を使う（コアの `noInterrupts()` で足りる） |
| 休止（standby）から起きても、リセットの印が何も残らない（2026-11-15） | `resetReason()` が休止からの起床として読み替える | 上の「共通」と同じ |

## CH32V20x / V30x / V407 / V467

| 起きること | コア | 自分で書くとき |
|---|---|---|
| standby に入るとき、PDDS と一緒に LPDS も立てると、V203C8T6 がアラームで起きなかった（2026-11-13） | EVT と同じく PDDS だけで入る（`ch32rv_power.c`） | standby に入る手順を自分で書くときは、EVT と同じく PDDS だけにする |

## CH32M030

| 起きること | コア | 自分で書くとき |
|---|---|---|
| 自動起床（AWU）の分周が固定で、1 カウント（約 150 ms）が最短。起動して最初の休止が、較正のために最大約 300 ms 長くなる | 最初の休止で 1 周期を測る（`ch32rv_power.c`） | 短い休止を繰り返す用途には向かない |
| I2C の入力クロックは HCLK そのもので、FREQ の上限（48 MHz）を超える | FREQ を 48 で頭打ちにする | I2C の速さは、規格の上限より遅めに出ることがある |
