# ファイルシステム(要件と比較)

2026-10-21 に着手、2026-11-04 に追加で測った。候補を同じ物差しで測ってから選ぶ。
ESP32 は FAT / SPIFFS / LittleFS を並べて選べる形なので、1 つに絞ることも前提にしない。
**採用案は最後の「採用案(2026-11-04)」。** 内蔵 Flash は対象から外す(ユーザーの判断、2026-11-04)。

## 使い道

| 使い道 | 媒体 | PC と同じ形式が要るか | 主に効く性質 |
|---|---|---|---|
| HTTP の設定サーバー(設定の JSON、Web の静的ファイル) | 内蔵 Flash、SPI の NOR Flash | 要らない | 電源断への強さ、摩耗の分散、小さいファイルの多さ |
| センサーノードのログ | SD カード | 要る(PC で読む) | 追記の速さ、電源断で失う範囲 |
| USB MSC デバイスで見せる SD をスケッチからも読む | SD カード | 要る | FAT。PC が触っている間の排他 |
| USB MSC ホスト(`mscMount()`、USB メモリ) | USB メモリ | 要る | FAT32、exFAT |
| UF2 での更新 | — | — | FS は要らない(仮想の FAT を見せるだけ) |

## 必須と「できるか見るだけ」

- 必須
  - FAT の読み書き(SD、MSC ホスト)。ディレクトリ、長いファイル名(英数字)。
  - Flash 向けで電源断に強い FS を、少なくとも 1 つ。
  - 共通のブロックデバイスの口(SD、MSC デバイス / ホスト、RAM ディスク、NOR Flash)の上に載ること。
  - 使わないスケッチには費用がかからないこと(ライブラリとして分ける)。
  - API は ESP32 の `FS` / `File`(`SD`、`LittleFS`、`FFat`)に合わせる。名前の付け方は Network と同じ方針(ESP 名の別名ヘッダーは置かない)。
- できるか見るだけ
  - exFAT(64 GB 以上の SDXC、大きい USB メモリ)。
  - 日本語のファイル名(FatFs のコードページ 932 は表が大きい)。
  - X035 クラス(Flash 62 KB)に FAT を載せること。

## 候補

ライセンスで使えないもの(GPL・LGPL・商用)は最初から外した。

| 候補 | 版 | ライセンス | 形式 | 言語 |
|---|---|---|---|---|
| FatFs | R0.16 | 1 条項 BSD 相当 | FAT12/16/32、exFAT | C |
| Petit FatFs | R0.03a | 同上 | FAT(読み出しと限られた書き込み) | C |
| SdFat | 2.3.1 | MIT | FAT16/32、exFAT | C++ |
| littlefs | 2.11.3 | BSD-3 | 独自(Flash 向け、電源断に強い) | C |
| SPIFFS | 0.3.7(上流の更新は少ない) | MIT | 独自(Flash 向け、ディレクトリなし) | C |

## 物差し

全候補を同じ処理(同じブロックデバイス、同じ手順)で測る。

1. **大きさ**: X035 と V307 で、Flash と RAM(静的、ヒープ、スタックの最大)を測る。機能の段(読み出しのみ、読み書き、長いファイル名、exFAT)ごとに測る。
2. **速さ**: チップの上の RAM ディスクで、FS 自体が使う CPU の時間を測る。
   - 16 KB の書き込みと読み出し。
   - 小さいファイル 20 個の作成。
   - 32 バイトの記録を 1000 回、毎回 sync して追記する。
   - SD での実測は、ベンチに SD を付けてから行う。
3. **電源断**: PC の上で、ブロックデバイスへの書き込みを n 回目で止め、再びマウントする。手順の中のすべての n で調べる。
   - マウントできるか。
   - sync 済みのデータが残っているか。
   - ほかのファイルが壊れていないか。
   - 失うのはどの範囲か。
   - 書きかけのセクタ(半分だけ書けた状態)も試す。
4. **NOR Flash での摩耗**: 消去 4 KB、書き込みは 1→0 だけ、という NOR を模して測る。
   - 同じ処理での消去回数と、その偏り。
   - FAT を NOR に載せる場合は、摩耗分散の層(FTL)が別に要る。この費用も数える。
5. **機能**: ディレクトリ、長いファイル名、タイムスタンプ、同時に開けるファイルの数、空き容量の取得、フォーマット。

## 測った結果(2026-10-21)

計測の仕組み(模擬の媒体、共通の作業、PC の電源断試験、チップのスケッチ)は、まだ作業用の場所にある。候補のソースは上流の版をそのまま使った。

作業の中身(全候補で同じ):
- 設定ファイル 300 B を作り、10 回書き換える。
- Web のファイル 2 つ(2000 B / 4000 B)を書く。
- ログに 32 B を 100 回追記する(毎回 close)。
- 16 KB のファイルを書いて読む(チップでは 4 KB)。
- 64 B の小さいファイルを 20 個作る。

### 大きさ(LTO 既定、FS を入れたときの増分)

| 候補・段 | X035 Flash | V307 Flash | RAM |
|---|---|---|---|
| Petit FatFs(読み出し、既存ファイルへの書き込み) | +1.6 KB | +1.6 KB | +0.6 KB |
| FatFs 読み出しのみ | +2.7 KB | +2.6 KB | +0.6 KB |
| FatFs 読み書き、8.3 形式の名前 | +6.7 KB | +6.6 KB | +0.6 KB |
| FatFs 読み書き、長いファイル名(コードページ 437) | +9.5 KB | +9.5 KB | +0.7 KB |
| 同上 + フォーマット | +10.4 KB | +10.4 KB | +1.2 KB |
| 同上 + exFAT | +16.5 KB | +16.5 KB | +1.4 KB |
| FatFs 長いファイル名、コードページ 932(日本語) | 入らない(13 KB 超過) | +68.5 KB | +0.7 KB |
| SdFat FAT(長いファイル名あり) | +9.4 KB ※ | +9.7 KB | +1.1 KB |
| SdFat FAT + exFAT | +15.7 KB ※ | +16.0 KB | +1.2 KB |
| littlefs | +16.0 KB | +16.1 KB | +1.8 KB |
| SPIFFS | +16.6 KB | +16.6 KB | +2.0 KB |
| SPIFFS(マウントのたびに SPIFFS_check) | +21.3 KB | +21.3 KB | +2.0 KB |

- ※ SdFat は `SdFat.h` の既定引数で `SS` を直接使う。X035 / X033 のバリアントには `SS` が無い(device-data に NSS の pad が無い)ので、そのままではコンパイルできない。計測では `SS` を外から与えた。
- RAM は、計測用の接続部で決めたバッファを含む(littlefs のキャッシュ 3 つ、SPIFFS の作業域・fd・キャッシュ)。設定で増減する。
- スタックの最大(V307 で実測): FatFs 1008 B(FF_FS_TINY で 592 B)、SdFat 640 B、littlefs 1184〜1216 B、SPIFFS 896 B。

### 電源断(PC 上、書き込みのすべての回で切る)

「失う」は、書き終えて close したデータが消えたか、別の中身になったこと。「壊れる」は、マウントはできるが新しいファイルを書けないこと。

| 候補 | 媒体 | 切った回数 | 失う | 壊れる | 失うもの |
|---|---|---|---|---|---|
| FatFs | 16 MB の SD 相当 | 404 | 40 | 0 | 書き換え中の設定ファイル(切り詰めてから書くため、旧も新も無い) |
| FatFs、一時ファイル + リネーム | 同上 | 424 | 20 | 0 | 設定ファイルが無い瞬間(FAT は置き換えのリネームができず、先に消す) |
| SdFat | 同上 | 426 | 0(半分書けたセクタで 1) | 0 | ※ |
| SdFat、一時ファイル + リネーム | 同上 | 486 | 20 | 0 | FatFs と同じ |
| littlefs | NOR 256 KB | 1056 | 0 | 0 | — |
| littlefs | 16 MB の SD 相当 | 326 | 0 | 0 | — |
| SPIFFS | NOR 256 KB | 1204 | 130 | 109 | 設定ファイル。追記中に切ると以後書けなくなる |
| SPIFFS、マウント時に SPIFFS_check | 同上 | 1204 | 239 | 0 | 書けなくはならないが、check がログを消す |

- 追記のログは、FAT でも close 済みの記録を失わなかった。
- ※ SdFat は、切り詰めとディレクトリの更新を close まで遅らせる。そのため、同じ大きさの書き換えなら旧か新のどちらかが残った。大きさが変わる書き換えまでは試していない。
- 半分だけ書けたセクタ / ページ / 消去でも、結果はほぼ同じだった。

### NOR での摩耗(PC 上、64 KB = 16 ブロック)

300 B の静的ファイル 20 個を置き、設定の書き換え(300 B)とログの追記(32 B)を 2000 回繰り返した。

| 候補 | 失敗 | 消去の回数(最少 / 平均 / 最多) | 書いた量 |
|---|---|---|---|
| SPIFFS | 0 | 64 / 65 / 66 | 4.2 MB |
| littlefs(キャッシュ 512 B) | 0 | 0 / 131 / 292 | 4.9 MB |
| littlefs(キャッシュ 256 B) | 300 B のファイル 20 個が 64 KB に入らない | — | — |

- littlefs は、キャッシュ(インライン)より大きいファイルに、1 つで消去ブロック 1 個(4 KB)を使う。小さいファイルが多いと容量を食う。
- littlefs は静的なファイルのブロックを動かさない(block_cycles 500)ので、摩耗が偏る。消去の総数も SPIFFS の 2 倍。
- FAT を NOR に載せるには、摩耗分散の層が別に要る(まだ測っていない)。

### 速さ(V307 96 MHz、RAM の媒体、作業 1 回)

模擬の媒体にかかった時間(実測した 1 回あたりの時間 × 回数)を差し引いた、FS 自体の CPU 時間。

| 候補 | 媒体 | 全体 | うち FS の CPU | ログ追記 1 回 | 書いた量 / 読んだ量 | 消去 |
|---|---|---|---|---|---|---|
| FatFs(長いファイル名) | 16 MB の SD 相当 | 17.5 ms | 約 7 ms | 82 µs | 190 KB / 166 KB | — |
| FatFs(FF_FS_TINY) | 同上 | 15.9 ms | 約 5 ms | 72 µs | 190 KB / 197 KB | — |
| SdFat | 同上 | 16.6 ms | 約 5 ms | 76 µs | 201 KB / 199 KB | — |
| littlefs | 32 KB のブロックデバイス | 280 ms | 約 272 ms | 1.7 ms | 151 KB / 550 KB | — |
| littlefs(キャッシュ 512 B) | NOR 40 KB | 811 ms | 約 769 ms | 7.4 ms | 179 KB / 1010 KB | 92 回 |
| SPIFFS | NOR 40 KB | 119 ms | 約 76 ms | 158 µs | 210 KB / 667 KB | 48 回 |

- littlefs の CPU 時間の多くは、ログの追記と小さいファイルの作成にかかった。媒体が小さい(40 KB)ほど、メタデータの詰め直しが増える。PC 上の 256 KB では、読む回数は 3 割ほど少なかった。
- 本物の NOR では、消去が 1 回 約 45 ms(W25Q の代表値)なので、消去の回数が効く。littlefs 92 回で約 4 秒、SPIFFS 48 回で約 2 秒。
- SPIFFS は既定の設定のままだと、V307 で境界のずれた 2 バイトのストアで止まった(mcause 6、`spiffs_object_append`)。`SPIFFS_ALIGNED_OBJECT_INDEX_TABLES 1` で直った。
- SD での実測は、ベンチに SD を付けてから行う。

### ここから言えること

- FAT(SD、USB メモリ、MSC)は、FatFs と SdFat で大きさ・速さ・電源断の性質がほぼ同じ。違いは次の点。
  - API: SdFat は Arduino 向けの C++ で、`File` に近い。FatFs は C で、口を自分で作る。
  - X035 でのビルド: SdFat は `SS` が要る。
  - 段の細かさ: FatFs は読み出しのみ(+2.7 KB)から段階的に削れる。
  - 日本語のファイル名: FatFs はコードページ 932 で +68.5 KB。
- Flash 向けでは、電源断に強いのは littlefs だけだった。代わりに、CPU 時間、消去の回数、小さいファイルの容量、摩耗の偏りで SPIFFS に負ける。SPIFFS は電源断で書けなくなり、check を入れるとデータを失う。
- X035(Flash 62 KB)には、FAT(読み書き、長いファイル名)で +9.5 KB、読み出しだけなら +2.7 KB で入る。

## 追加の測定(2026-11-04)

計測の仕組みは 2026-10-21 のものを広げた(作業用の場所、上流のソースはそのまま)。

### FAT を NOR に載せる(ESP32 の FFat と同じ形)

ESP-IDF の wear_levelling(Apache-2.0)を PC に移し、FatFs をその上に載せた。NOR は 1 MB、作業は前と同じ。
wear_levelling の 3 つの形を測った: 4 KB セクタ(`WL_Flash`、FAT のセクタ = 消去ブロック)、512 B セクタの
性能優先(`WL_Ext_Perf`)と安全優先(`WL_Ext_Safe`)。

| 候補 | 書いた量(中身の何倍か) | 消去 | 電源断で失う / 壊れる(切った回数) | 失うもの |
|---|---|---|---|---|
| littlefs | 6.5 倍 | 113 回 | 0 / 0(1056) | — |
| SPIFFS | 2.3 倍 | 少ない | 130 / 109(1204) | 設定ファイル。書けなくなる |
| FatFs + WL 4 KB | 67 倍 | 495 回 | 851 / 47(23919) | 設定、ログ、**触っていない小さいファイル** |
| FatFs + WL 512 B 性能優先 | 74 倍 | 543 回 | 3627 / 362、マウント不能 181(24963) | 同上、Web のファイル、16 KB のファイル |
| FatFs + WL 512 B 安全優先 | 135 倍 | 1801 回 | 8683 / 0(38696) | 同上 |

- 4 KB セクタの FAT は 128 セクタ(512 KB)より小さい媒体を作れない(FatFs の制限)。256 KB の NOR では作れなかった。
- FAT のセクタを書くたびに、消去ブロックを消してから書く。消えた瞬間に切れると、そのブロックにある別のファイルや
  FAT 表が失われる。安全優先の形は隣のセクタを退避するが、書いている FAT 表自体は守れない。
- 摩耗(設定 300 B の書き換えとログ 32 B の追記を 2000 回、1 MB):

| 候補 | 消去の総数 | 1 ブロックの最多 | 1 回あたりの消去 | 1 回にかかる消去の時間(45 ms / 回) |
|---|---|---|---|---|
| littlefs | 4000 | 18 | 2 | 約 90 ms |
| SPIFFS | 563 | 3 | 0.3 | 約 13 ms |
| FatFs + WL 4 KB | 18481 | 644 | 9.2 | 約 0.4 秒 |
| FatFs + WL 512 B 安全優先 | 63501 | 2466 | 32 | 約 1.4 秒 |

### FAT の相互運用(Linux の mkfs と fsck)

Linux の `mkfs.fat` / `mkfs.exfat` で作った像に、各エンジンで作業と長い名前・大文字小文字の混ざった名前・
70 KB のファイル・同じ頭の名前 40 個を書き、`fsck.fat -n` / `fsck.exfat -n` で調べた。像は区画なし(USB メモリに
多い)と MBR の区画あり(SD カードの形)の両方。

| | FAT12 | FAT16 | FAT32 | exFAT | 区画なし | 自分で mkfs した像 |
|---|---|---|---|---|---|---|
| FatFs R0.16 | 通る | 通る | 通る | 通る | 通る | 通る(fsck もきれい) |
| SdFat 2.3.1 | マウントできない | 通る | 通る(FSInfo の空き数を直さない。fsck が警告) | 通る | マウントできない | — |

- SdFat は、頭の 6 文字が同じ長い名前を同じミリ秒の中で 3 つ作ると、3 つ目が失敗する(短い名前のハッシュを
  `millis()` から作り、やり直しても同じ値になる)。
- PC で書いたファイルを読む向きは試せなかった(ループのマウントに root が要り、mtools のビルドは断られた)。

### FatFs で SdFat と同じ遅い切り詰め

前の測定で、SdFat は書き換え中の電源断で設定ファイルを失わなかった(切り詰めを close まで遅らせる)。
FatFs でも、`"w"` を「上書きして close で切り詰める」にすると同じになった(16 MB の SD 相当)。

| 書き方 | 切った回数 | 失う | 半分書けたセクタ |
|---|---|---|---|
| FatFs、開くときに切り詰める(`FA_CREATE_ALWAYS`) | 404 | 40 | 40 |
| FatFs、close で切り詰める | 374 | 0 | 10(中身が新旧混ざる) |

### 共通の API の費用

ESP32 の `FS` / `File` と同じ形の層(仮想関数の `FileImpl` / `FSImpl`、`File` は `Stream`)を試作し、同じ処理
(設定を書く、追記、読み戻し、mkdir、rename、ディレクトリの一覧)で測った。同時に開けるファイルは 2。
RAM はスケッチの 300 B のバッファを含む(媒体の RAM は除いた)。

| | X035 Flash | X035 RAM | V003 Flash | V003 RAM |
|---|---|---|---|---|
| FatFs 直接(長いファイル名、読み書き) | +9.7 KB | +0.7 KB | +9.4 KB | +0.7 KB |
| 層を通す | +12.4 KB | +2.0 KB | — | — |
| 層を通す、FF_FS_TINY・ファイル 1 つ | — | — | +12.1 KB | +0.9 KB |
| FatFs 直接、読み出しのみ | +3.4 KB | +0.6 KB | +3.1 KB | +0.6 KB |
| 層を通す、読み出しのみ | +5.0 KB | +1.9 KB | +5.0 KB(TINY、1 つ) | +0.7 KB |
| 層を通す、読み出すだけのスケッチ、ライブラリは読み書きの構成 | +12.2 KB | +2.0 KB | — | — |
| littlefs 直接 | +16.1 KB | +1.0 KB | — | — |
| littlefs、層を通す | +18.6 KB | +2.1 KB | — | — |
| FatFs と littlefs の両方、層を通す | +30.8 KB | +4.3 KB | — | — |

- 層の分は 1 エンジンあたり約 2.5 KB。使っていない操作(remove、exists、seek、空き容量)も仮想関数から
  リンクされる。読み出すだけのスケッチでも、ライブラリが読み書きの構成なら書く側がすべて入る(+7 KB)。
- RAM の差の多くは開けるファイルの数。FatFs の FIL は 1 つ 550 B(FF_FS_TINY なら 40 B、代わりにボリュームの
  バッファを共有するので、複数のファイルを交互に読み書きすると遅い)。
- V003(16 KB / 2 KB)は、層を通した読み出しのみ(+5 KB)なら SPI の SD のドライバと一緒に入る。読み書きは
  +12 KB で、SPI と SD のドライバを足す場所が無い。

## 採用案(2026-11-04)

- **ファイルシステムは FatFs だけ。** SD(SPI、SDIO)、H417 の eMMC、USB のホストの MSC、RAM ディスク、
  USB の MSC デバイスで PC と共有する媒体。SdFat と大きさ・速さは同じで、相互運用(FAT12、区画なし)、
  段の細かさ(読み出しのみ、exFAT、コードページ)で上回る。SdFat の電源断への強さは、`"w"` を close で
  切り詰めることで同じにできた。
- **外付けの SPI NOR Flash にはファイルシステムを載せない**(ユーザーの判断)。NOR は、フォントや画像を決まった
  番地に置く生のイメージとして使うのが普通で、ファイルが要るなら SD を使えばよい。要るのは読み書きと消去の
  ドライバで、ファイルシステムとは別に考える。少しの設定を電源断に強く残すなら I2C の EEPROM(バイト単位で
  書けて消去が要らない)。
  - そのため littlefs も入れない。測った結果(上)は、内蔵 Flash を扱うことになったときのために残す。
  - FAT を NOR に載せる形(ESP32 の FFat、EVT の MSC U-Disk)も入れない。書く量が 10〜20 倍、小さい書き換え
    1 回の消去が 0.4〜1.4 秒、電源断で触っていないファイルまで失う。
- **SPIFFS も入れない。** 電源断のあと書けなくなり、上流の更新も止まっている。
- API は ESP32 の `FS` / `File` の形で、エンジンをあとから足せるようにしておく。名前は ESP32 に合わせる
  (`FS`、`File`、`SD`)。ESP の名前を付けた別名ヘッダーは置かない。
- 小さい系列(X035、V003)の段(読み出しのみ、exFAT の有無、開けるファイルの数)は、メニューにするかを
  数を見て決める。V003 は読み出しのみ。

### まだ測っていないもの(機材が要る)

- SD カード(SPI)の速さと相性(SDHC の FAT32、SDXC の exFAT)、SDIO(V30x / V40x / H41x)、H417 の eMMC(SDMMC)。
- USB のホストの MSC で市販の USB メモリ。
- PC で書いたファイルを読む向き(USB の MSC デバイスで PC にマウントさせる)。

## 決めたこと

- 同梱する(2026-11-04、ADR-0013 の補足)。
- ライブラリは `libraries/FS`(2026-11-04 に入れた)。`FS.h`(ESP32 の `FS` / `File`)、`FSBlockDevice.h`
  (`fs::BlockDevice`、`fs::RamBlockDevice`)、`FatFS.h`(FatFs のボリューム)。FatFs は `src/fatfs/` に取り込み
  (`tools/vendor/vendor_fatfs.py`、作者の patch 1・2 を当てる)、設定は `src/ffconf.h` と `src/FSConfig.h`。
  USB の MSC デバイスで PC と共有する口は `CH32RVUsbDeviceMscBlockStorage`(CH32RVUsbDevice、ヘッダーだけ)。
  - 既定の構成と大きさは libraries/FS/README.ja.md。小さい系列(V002〜V007、M007、X033、X035、M030)は exFAT・
    タイムスタンプ・フォーマットなし、ボリューム 1 つ、FF_FS_TINY。V003 は長い名前もなし(作業用のバッファ
    512 B が 2 KB の RAM に入らない)、開けるファイル 2 つ。
  - 試験は tests/unit/fs(ホスト、Linux の mkfs と fsck)と、tests/peer/usb の usb-peer-fs(X035 と ESP32-S3。
    DUT の FatFS と S3 の ESP-IDF の FAT が、USB の MSC で 1 つのボリュームを受け渡す。2026-11-04 に通った)。
  - SD(SPI)は `libraries/SD`(`SD`、`SDSPIBlockDevice`。CRC 付き、複数ブロックの転送)、SD(SDIO)は
    `libraries/SD_MMC`(`SD_MMC`、`SDIOBlockDevice`。V30x / V4x7 / H41x、1 / 4 ビット、CPU が FIFO を動かし
    ハードウェアのフロー制御)。2026-11-04 に入れた。SPI は tests/unit/fs の模擬カードで確かめ、SDIO はビルドだけ。
    実機の確認は後日(SPI のカードは V20x の CH32V203C-R1 などのスロット、SDIO は CH32V307V-R2 の評価ボードか互換機)。
  - eMMC(H41x の SDMMC)と USB ホストの MSC のブロックデバイスはまだ無い。
