# コードフラッシュの raw アクセス(実験の記録)

2026-10-21〜22 の実験の記録。永続化(保存の API)を設計するときに根拠にする数字を集めた。**設計はまだしていない。**

方法:
- 動いているスケッチから、EVT の手順どおりにフラッシュ制御のレジスタを直接操作した。
- 時間は TIM2 を 1 MHz で回して測った。CPU が止まっても数え続ける。
- 試験の範囲は、フラッシュの末尾 4 KB。

対象: V003F4U6(24 MHz)、V103R8T6(72 MHz)、V307VCT6(96 MHz)、X035C8T6(48 MHz)、L103C8T6(8 MHz)、H417QEU6(V3F 100 MHz)。

## 消去と書き込みの時間

| 系列 | 標準のページ消去 | 高速のページ消去 | 32 KB のブロック消去 | 高速のページ書き込み | 2 バイトの書き込み |
|---|---|---|---|---|---|
| V003 | 1 KB:50.0 ms | 64 B:3.13 ms | — | 64 B:2.81 ms | 2.81 ms |
| V103 | 1 KB:25.0 ms | 128 B:3.13 ms | — | 128 B:2.80 ms | 2.80 ms |
| V307 | 4 KB:17.2 ms | 256 B:17.0 ms | 18.4 ms | 256 B:1.50 ms | 2.11 ms |
| X035 | 1 KB:3.12 ms | 256 B:2.92 ms | (試していない) | 256 B:1.62 ms | なし |
| L103 | 2 KB:6.62 ms | 256 B:6.42 ms | (試していない) | 256 B:2.12 ms | なし |
| H417 | 8 KB:2.4 ms(コアの ch32rv_flash_erase) | — | — | 256 B:0.67 ms、4 KB:10.7 ms | — |

- V307 の消去は、大きさによらず約 17 ms。
- 高速のページ書き込みでは、ページのバッファに入れる時間は別にかかる。V003 で 86 µs、V103 で 35 µs、V307 で 22 µs、X035 で 68 µs、L103 で 281 µs(8 MHz)。
- 2 バイト単位で書くと、1 回あたり高速ページ 1 枚と同じくらいかかる。256 B を 2 バイトずつ書くと、V307 で約 270 ms(高速ページなら 1.5 ms)。
- クロックを変えたときに時間が変わるかは、測っていない。

## 処理中の CPU と割り込み

| 系列 | RAM のコード | フラッシュのコードを呼ぶ | 割り込み(処理がフラッシュにあるもの) |
|---|---|---|---|
| V003、V103、X035、L103 | 動き続ける | 処理が終わるまで止まる(消去なら 3〜50 ms) | 処理が終わるまで入らない。来ると CPU ごと止まる |
| V307 | 動き続ける | 止まらない | 入る(SysTick 17 回/17 ms、そのまま) |
| H417(全部 RAM で実行) | 動き続ける | —(コードは RAM) | 入る。millis() も遅れない |

- 止まる系列では、SysTick 割り込みが処理の間に 1 回しか通らないので、`millis()` が遅れる。X035 の 3 ms の消去で約 2 ms 遅れる。
- 止まる系列では、割り込みを止めておくと、RAM のループは 3 倍回った(X035)。割り込みが来ると、フラッシュにある処理に入ろうとして止まる。
- V307 は、起動時にフラッシュを待ちなしの領域へ写し、そこから実行しているためと考えている。
- USB の割り込みも、止まる系列では処理の間は入らないはず。X035 で USB が切れないかは、PC につながった X035 がベンチに無いので測っていない。

## 消去したときの値と、消さずに書き直す

| 系列 | 消去後の値 | 0 の向きに書き直す(消去なし) |
|---|---|---|
| V003、V103、X035、L103 | 0xFFFFFFFF | できた |
| V307、H417 | 0xE339E339 | 高速ページはできない(64 語中 58〜64 語が崩れる)。V307 の 2 バイト単位は、今回は合っていた |

V307 と H417 は、消去後の値が 0xFF ではないことから、データを変換して(暗号化か誤り訂正か)保存しているとみている。追記して使う形は、この 2 つでは成り立たない。

## 処理の途中で止めたとき

### リセットで止める(TIM2 で決めた時刻 d µs に、RAM のコードからシステムリセット)

| 系列 | 消去の中身の時間割 | 書き込みの中身の時間割 |
|---|---|---|
| X035(256 B) | 0〜40 µs 変化なし。50〜340 µs 全部 0。350〜540 µs 消している途中(読むたびに値が変わる語あり)。550 µs 以降 消去済み(BSY は 2.92 ms まで) | 0〜35 µs 変化なし。40〜85 µs 書いている途中。88 µs 以降 書き終わり(BSY は 1.62 ms まで) |
| V103(128 B) | 50〜350 µs 全部 0。約 400 µs 途中。450 µs 以降 消去済み | 32〜48 µs 途中。64 µs 以降 書き終わり |
| V003(64 B) | 75〜350 µs 全部 0。375〜425 µs 途中。450 µs 以降 消去済み | 24〜48 µs 途中。56 µs 以降 書き終わり |
| V307、H417 | 開始の直後(V307 は 50 µs〜、H417 は 100 µs〜)にリセットしても、最後まで済んでいた | 同じく最後まで済んでいた |

- 止まる系列では、消去は「いったん全部 0 に書いてから消す」順に進む。途中で止まると、全部 0、消しかけ、読むたびに値が変わる語のどれかが残る。
- 中身がそろったあとも、BSY は長く続く。X035 の消去では、途中で止まると困る時間は全体の約 17%、書き込みでは約 3%。
- V307 と H417 は、システムリセットではフラッシュの処理が止まらなかった。

### 電源断(uhubctl で、プローブと DUT の USB の電源を切る)

| 系列 | 切った回数 | 書きかけが残った回数 | 中身 |
|---|---|---|---|
| V307 | 30 | 3 | 1 ビットだけ違う語。一部の語だけ書けたページ |
| V003 | 30 | 4 | 消しかけ(3 回は読むたびに値が変わる) |
| V103 | 30 | 1 | 全部 0(消去の前半) |

- 残りの回は、ページ全体が消去済み、パターン A、パターン B のどれかにそろっていた。
- 電源を切ると、VDD は 2.1 ms(記録の間隔)より速く落ちた(V307 で、3.20 V のまま記録が止まる)。切れてから動き続ける余裕はほとんどない。
- 読むたびに値が変わる語があるので、CRC で確かめる場合も、読むたびに結果が変わりうる。

## 書き込みのツールとの関係

| 経路 | 末尾のデータ |
|---|---|
| ch32rv flash、既定の `--erase keep-store`(ch32rv 0.25 から。ELF の `.ch32rv_store` を退避して書き戻す) | 残る |
| ch32rv flash `--erase chip`(Erase Flash の All Flash) | 消える |
| ch32rv flash `--erase sector`(イメージが覆うページだけを消す) | 残る |
| H417 の DFU(`boot dfu flash`、イメージのブロックだけ書く) | 残る |

Arduino の書き込みボタンは、ツール → Erase Flash の既定(Keep Store)で `--erase` を渡さず、ch32rv の既定の keep-store で書く。HID と ISP の経路は測っていない。

## リンカーで末尾を確保する

`sections.ld` の写しに、フラッシュの末尾に置く NOLOAD のセクションを足した(作業用の写しで試し、コアには入れていない)。

```
.ch32rv_store ORIGIN(FLASH) + LENGTH(FLASH) - SIZEOF(.ch32rv_store) (NOLOAD) :
{
    KEEP(*(.ch32rv_store*))
} >FLASH
```

- 何も置かないスケッチ: 大きさは変わらない(2736 B のまま)。確保もされない。
- 1 KB を置いたスケッチ: 0xF400〜0xF7FF(X035 の 62 KB の末尾)に置かれる。NOLOAD なので書き込むイメージ(bin)には入らない。
- Arduino が表示する使用量には、確保した分が入らない。それでも、コードが末尾まで伸びればリンカーが重なりを見つけてエラーにする(60 KB を確保して確かめた)。

## 実験の途中で見つかったこと

- **`.highcode` が、V003 以外では RAM に写されない。** crt0 は `CH32RV_HIGHCODE` を定義した系列(V003 だけ)でしか写さない。それ以外では、`.highcode` に置いた関数は RAM に場所だけ取られ、呼ぶと落ちる(X035 で、mcause 3 で止まった)。今回はスケッチの `setup()` で写した。
- **V003 で、長い `printf` の行が途中で止まった。** 当初は「ヒープの確保に失敗して捨てる」とみたが、2026-10-28 の測定では、`printf` がスタックを 500 B 余り使ってスタックの確保（512 B）をはみ出し、ヒープで組み立て中の行を壊していた（[printf と浮動小数](printf-float.ja.md) で直した）。
- **V103 で、電源を入れた直後だけ、リンカーの定数から計算したはずの値が狂った**(原因は調べていない)。デバッガからリセットしたあとは正しかった。リンカーのシンボルどうしのポインタの引き算(未定義の動作)を整数の引き算に直しても、電源を入れた直後には同じことが起きた。

## 測っていないこと

- X035 で、フラッシュの処理中に USB が切れないか(PC につながった X035 がベンチに無い)。
- L103 の、途中で止めたときの時間割(OEP 経由のコンソールで、試験のスクリプトをまだ合わせていない)。
- V20x、V006、V205、V407、X315、M030 の数字(ベンチの対象に入っていない)。
- 書き換えの寿命、クロックを変えたときの時間、割り込みの処理を RAM に置いた場合(ベクター表はフラッシュにある)。
