# フラッシュへの保存

内蔵のコード用フラッシュに、スケッチからデータを書いて残す方法です。

## まず外部への保存を考える

**長く残したいデータは、外部に保存するのが推奨です。**

- SD カード（SPI）: ファイルとして残せます。FAT に何を使うかは [filesystem.ja.md](filesystem.ja.md) で検討しています。
- I2C の EEPROM: 1 バイト単位で書き換えられ、寿命も長い部品です（例は TODO の `I2CEeprom`）。

内蔵のフラッシュに書くこともできますが、次の制約があるので、**上級者向けの選択肢**とします。

| 制約 | 中身 |
|---|---|
| 寿命 | 消去の回数に限りがあります。1 万回の系列もあります（下の表）。60 秒ごとに書くと、1 万回の系列は約 7 日でだめになります。 |
| 書き込み直し | スケッチを書き込み直すと、保存した中身が消えることがあります（経路とツールの版による）。残った場合は、別のスケッチが古いデータを読みます。 |
| 消す単位 | 決まった単位（64 B〜8 KB）で丸ごと消します。1 バイトずつは書き換えられません。 |
| 書く単位 | 決まった大きさのページ（64〜256 B）で書きます。消したあとの値は系列で違います（0xFF か 0xE339）。0xE339 の系列では、消さずに重ねて書けません。 |
| 書いている間 | V003、V103、X035、L103 などでは、数 ms の間 CPU と割り込みが止まります。UART の受信が落ち、`millis()` が遅れます。 |
| 電源断 | 書いている途中で電源が切れると、その単位の中身は壊れます。前の値を残したいときは、2 か所に交互に書きます。 |

## 何を使うか

| したいこと | 使うもの |
|---|---|
| 数個の設定を残す（電源断で既定値に戻ってよい） | 例 [FlashSettings](../libraries/CH32RV/examples/FlashSettings/README.ja.md) |
| 数個の設定を残す（電源断でも前の値を残す） | 例 [FlashSettingsTwoBanks](../libraries/CH32RV/examples/FlashSettingsTwoBanks/README.ja.md) |
| 自分で形式を決める | 下の関数を直接使う |

`EEPROM.h` は用意しません。Arduino の EEPROM の API は 1 バイトずつ書き換えられる前提ですが、フラッシュでは単位ごとに消すので、同じ使い方をすると寿命と時間を大きく使います。

## API

`#include <ch32rv_flash.h>` で使います。どの系列でも同じ名前で使えます。**どの関数も、呼ばなければ大きさは 0 です。**

```c
CH32RV_FLASH_ERASE_SIZE     // 消す単位
CH32RV_FLASH_WRITE_SIZE     // 書く単位(ページ)
CH32RV_FLASH_ERASED_WORD    // 消したあとの 1 語の値
CH32RV_FLASH_STORE(name, size);   // フラッシュの末尾に size バイト(消す単位に切り上げ)を確保する
CH32RV_FLASH_OFFSET(p)            // 確保した領域の番地を、関数に渡すオフセットにする

bool ch32rv_flash_erase(uint32_t offset, uint32_t length);                 // 範囲を消す
bool ch32rv_flash_write(uint32_t offset, const void *data, uint32_t length); // 消した範囲に書く
bool ch32rv_flash_erase_page(uint32_t offset);                             // 1 単位を消す
bool ch32rv_flash_write_page(uint32_t offset, const uint32_t *data);       // 1 ページを書く
bool ch32rv_flash_rewrite_page(uint32_t offset, const uint32_t *data);     // 1 単位を消して、先頭の 1 ページを書く
uint32_t ch32rv_flash_size(void);
uint32_t ch32rv_flash_erase_size(void);
```

- **確保:** `CH32RV_FLASH_STORE(store, 2 * CH32RV_FLASH_ERASE_SIZE);` と書くと、リンカーが `store` をフラッシュの末尾に置きます。書き込むイメージには入りません。コードと重なればリンクで止まります。
- **読む:** `store` を普通の配列として読みます。
- **書く:** 上の関数で書きます。`store[i] = x` のように直接は書けません。
- **オフセット:** フラッシュの先頭からのバイト数です。どの系列でもリンクの番地と同じなので、`CH32RV_FLASH_OFFSET(store)` で求めます。
- **断るもの:** 次の範囲では、何もせずに偽を返します。
  - 単位にそろっていない
  - 長さが 0
  - フラッシュの外
  - 動いているプログラム自身に重なる
- **偽を返すほかの場合:** 書き込み保護のエラーと、時間切れです。このときの中身は決まりません。
- **H415、H416、H417:** プログラムが RAM で動くので、自分自身のイメージも書き換えられます（DFU が使います）。
- **データの境界:**
  - `ch32rv_flash_write` の `data` は、どこにそろっていてもかまいません。
  - `*_page` の関数は、語（4 B）の境界にそろった `uint32_t` の並びを受け取ります。

### 系列ごとの値

| 系列 | 消す単位 | 書く単位 | 消したあとの値 | 書く間に CPU が止まる | 寿命（25 ℃、最小） |
|---|---|---|---|---|---|
| V003 | 64 B | 64 B | 0xFFFFFFFF | 止まる | 1 万回 |
| V002、V004〜V007、M007 | 256 B | 256 B | 0xFFFFFFFF | 止まる（V006） | 10〜30 万回 |
| M030 | 128 B | 128 B | 0xFFFFFFFF | 未測定 | 1 万回 |
| V103 | 128 B | 128 B | 0xFFFFFFFF | 止まる | 1 万回 |
| L103、M103 | 256 B | 256 B | 0xFFFFFFFF | 止まる | 30 万回 |
| X033、X035 | 256 B | 256 B | 0xFFFFFFFF | 止まる | 30 万回 |
| V205 | 256 B | 256 B | 0xFFFFFFFF | 止まる | 30 万回 |
| V203、V208 | 256 B | 256 B | 0xE339E339 | 止まらない（V203） | 1 万回 |
| V303、V305、V307、V317 | 256 B | 256 B | 0xE339E339 | 止まらない | 1 万回 |
| V407、V467 | 4 KB | 256 B | 0xE339E339 | 未測定 | 5 万回 |
| X305、X315 | 4 KB | 256 B | 0xE339E339 | はっきりしない（X315） | 5 万回 |
| H416 | 4 KB | 256 B | 0xE339E339 | 止まらない（RAM で動く） | 5 万回 |
| H415、H417 | 8 KB | 256 B | 0xE339E339 | 止まらない（RAM で動く） | 5 万回 |

- 消したあとの値が系列で違うので、保存したかどうかは、版の値や CRC で見分けます。空かどうかでは見分けません。
- H415 と H417 の 8 KB は、960K のモード（`FLASH_CFGR0.DBMODE`）のときの値です。
- 4 KB や 8 KB の系列で 1 ページ分だけ使う場合も、確保は消す単位の分だけ要ります。

## 使い分けと費用

何もしないスケッチとの差（バイト、LTO あり（既定）、12 系列の幅）です。RAM は増えません。書く関数は、作業用にスタックを使います。ページを 1 枚組み立てる場合は、ページ 1 枚分です。

| 使い方 | 費用 |
|---|---|
| `erase_page` だけ | +192〜212 |
| `write_page` だけ（消さずに書き足す） | +280〜312 |
| `rewrite_page`（消して 1 ページ書く） | +304〜372 |
| `erase_page` のあと `write_page` | +384〜412 |
| `rewrite_page`、オフセットを実行時に決める | +320〜388 |
| `erase_page` と `write_page`、オフセットを実行時に決める | +400〜428 |
| `erase` と `write`、オフセットと長さを実行時に決める | +504〜560 |
| 5 つの関数を全部使う | +572〜624 |
| 例 FlashSettings の読み書きの部分 | +436〜512 |
| 例 FlashSettingsTwoBanks の読み書きの部分 | +660〜744 |

- **消して書き直すなら `rewrite_page` を使います。** `erase_page` と `write_page` を続けて呼ぶより、約 60 B 小さくなります。
- **範囲の関数（`erase` と `write`）は、長さが定数なら、1 単位の関数と同じ大きさになります。** LTO が、使い方に合わせて作り直すためです。長さを実行時に決めると、約 100〜150 B 増えます。
- **LTO なし**（Optimize のメニューで選ぶ）では、大きくなります。
  - `erase_page` だけで +296〜312 B、`rewrite_page` で +456〜536 B、全部使うと +776〜836 B です。
  - 関数をヘッダーにインラインで置くと、LTO なしでも 50〜120 B 小さくなりました。ただし、複数のファイルから使うとコードが重複します。そのため、コアの .c に置いています。
- **境界にそろっていないデータ:** `ch32rv_flash_write` は、バイトを組み立てて読みます。`memcpy` を使うと newlib の `memcpy`（rv32imac で 298 B）が入るので、使っていません。
- **スケッチで足すときの費用**（V003 で測った値）:
  - `millis()` の補正を固定の値で行う：+24 B。CPU が止まる系列で、1 ページあたり V003 で約 4 ms、X035 で 2〜3 ms 遅れます。V203 は遅れません。
  - 書いたあとに読み直して比べる：+32 B。
  - 割り込みを止める処理は、勧めません。止めても、正しく書けるかは変わりませんでした。`millis()` が余計に遅れるだけでした。

## 確かめたこと

2026-10-28、ベンチの 12 系列（V003、V006、M030、V103、X035、L103、V205、V203、V307、V407、X315、H417）で確かめました。

- **全部の関数：** 消す、書く、消して書く、2 単位をまとめて消す、境界にそろっていないデータから書く、を確かめました。
- **断ること：** 範囲の外、単位にそろっていない、長さ 0、プログラム自身、の 4 つです。
- **2 つの例：** 保存して、リセットのあとに読み戻せました。

記録は [PERSIST-01 の measurements.ja.md](../planning/core-redesign/tasks/PERSIST-01/measurements.ja.md)（M15〜M19）にあります。

**まだ確かめていないこと：**
- 電源断の試験：2 面の形で、前の値が残るか。
- 書く間に CPU が止まるか：M030、V407、X315（X315 は、2.8 ms の消去で `millis()` が 2 しか進まなかった）。
- 書き込みの経路ごとに、保存した中身が残るか：工場の ISP、HID のブートローダー、WCH-Link（CH549）など。
