## 2. すべてに当てる規則(決定の当てはめ)

- **照会は観測だけ。** `read()`、`getCount()`、`available()` は、裏で何かを進めない。
- **待たない。** 受理は try、結果はオブジェクトが持ち、利用者が取りに来る。blocking の版は標準に付けない。
- **利用者の関数は `deliverEvents()` の中でだけ動く。** 割り込みから利用者の通知 callback を直接呼ばない。例外は `attachInterrupt()` と同じ性格の「利用者が割り込みの関数として渡したもの」だけ。
- **裏の仕事は `begin()` で登録する**(`ch32rv_service`)。利用者に `maintain()` を書かせない。
- **使わなければ 0 B。** 登録の表や予約 RAM を常設しない。
- **名前は ESP32 と意味が同じときだけ同じにする。** ESP 名のヘッダー(`esp_sleep.h` など)は作らない。
- **能力の無い系列でもビルドは通す。** 実行時に `begin()` などが false を返す。端子しだいで決まるもの(どのタイマーのチャネルか)も同じ。

## 3. 時間の段: ソフトのタイマーで足りないときにハード

時間に関わる機能は、次の段で考える。上の段で足りるなら、下の段を使わない。下の段ほど正確だが、資源(TIM、割り込み)を使い、書ける処理も狭くなる。

| 段 | 仕組み | 正確さ | 動く文脈 | 今あるもの |
|---|---|---|---|---|
| 1 | `Deadline` / `Period` を `loop()` で確かめる | `loop()` の戻りしだい(ms) | 通常 | SyncKit。遅れたら 1 回にまとめ、`missed()` で数が分かる |
| 2 | `Work` を `wakeOn(Deadline)` / `wakeEvery(Period)` で起こす | 段 1 と同じ | 通常(`runOnce()` の中) | TaskKit |
| 3 | ハードのタイマーの割り込みで合図する | µs(割り込みの遅れの分ずれる) | 割り込み(合図だけ) | ライブラリ向けのリース API だけ。利用者向けは無い(TIM-01) |
| 4 | ハードが直接やる | クロック単位 | なし | PWM、`tone()`、Servo。入力捕捉・エンコーダ・ADC のトリガは無い |
| 休止中 | RTC のアラーム、AWU、LPTIM | 低速のクロックしだい | 起床の要因になるだけ | 無い |

決めること:
- **Ticker(TIM-02)は作らず、段 1 の `Period` をその代わりと案内する案。** ESP32 の Ticker は別の task で callback を呼ぶが、それは D-3(自分の関数は自分が呼んだ場所で動く)に合わない。`deliverEvents()` で配る Ticker を作る案もあるが、`Period` との違いが名前だけになる。
- **段 3 の利用者向け API(TIM-01)は、`attachInterrupt()` と同じ性格の「周期・単発の割り込みで合図」に限る。** 中身は今のリース API の上に作る。これは A の 6 項目の後でよい。
- 段 4 の入力捕捉・エンコーダは「割り込み無しで、ハードが更新し続けた値を読む」形にする(5.4)。段 3 の通知は付けない。

## 4. 項目をまたぐ仕組み

### 4.1 クロックの構成(HSE)

今の事実:
- CPU Clock のメニューは HSI と、HSI からの PLL だけ。
- HSE の周波数を、ライブラリがそれぞれ持っている。USB HS は `hseHz`(既定 8 MHz)、Ethernet は `ETH.setHseFrequency()`(V307 / V317、既定 8 MHz)、H417 の USB SS も自分で使う。
- HSE は X035(X033)以外の全系列にある(device-data の clock_sources)。水晶があるか、その周波数は、基板しだい。

案:
- ボードメニューで HSE を選ぶ(英語の表示。例: `Clock Source: Internal (HSI)` / `External crystal 8 MHz` / `External crystal 25 MHz`)。選ぶと `CH32RV_HSE_HZ` が決まり、CPU のクロックも HSE から作る。
- **HSE の周波数の正本を、このメニューの 1 か所にする。** ライブラリの `hseHz` / `setHseFrequency()` は、このメニューの値を既定値として使うか、廃止する。
- HSE が立ち上がらないときは、止まらずに HSI で同じ周波数を作れれば作る。作れなければ HSI のまま動く。どちらの場合も、`CH32RV` から分かるようにする(例: `clockSource()`)。HSE で決まった周波数が要るライブラリ(Ethernet など)は `begin()` で false を返す。
- 動作中のクロックの切り替えの API は作らない(決定のとおり)。

ほかの項目との接点:
- ストップから起きると、クロックは HSI に戻る。コアが選ばれた構成に戻す。HSE なら、水晶が立ち上がるまでの時間(ms 程度。実測する)が起床の遅れに加わる。
- RTC のクロックを HSE/128 にすると、ストップ中は止まる。

### 4.2 時刻源と時刻の不連続

今の事実:
- `millis()` は SysTick の 1 ms ごとの割り込みで数える。`micros()` はそれに SysTick のカウンタを足す。
- `time()` / `gettimeofday()` は `millis()` を 64 ビットに広げ、`settimeofday()` のずれを足したもの。SNTP(NetworkTime)は `settimeofday()` で合わせる。
- SyncKit の `Deadline` / `Period` は `millis()` を使う。

止まる場面:

| 場面 | `millis()` | 分かる経過時間 |
|---|---|---|
| ストップ(CPU とクロックが止まる) | 止まる | RTC か AWU / LPTIM で測っていれば分かる |
| スタンバイ | リセットされる | RTC があれば分かる |
| フラッシュの消去・書き込み(V003、V103、X035、L103 では CPU が止まる。3〜50 ms) | 割り込みが遅れる。SysTick のカウンタが進み続けるかは未測定 | カウンタが進み続けるなら、取り戻せる |
| デバッガがクロックを変えたあと(今もある) | 補正済み | — |

案:
- **経過が分かる場合は、`millis()` をその分だけ進める。** `Deadline` / `Period` はそのまま正しく動く。精度は、測ったクロック(LSI なら数 %)に従う。
- **経過が分からない場合は、`millis()` を進めずに、時刻の世代の番号(time domain)を 1 つ進める。** 利用者とライブラリは、`CH32RV.timeDomain()` の変化で「期限の判断ができない」と知る(決定 G2 の「未知の経過を推定で埋めない」)。`Deadline` に世代を持たせるかは、相談事項にする(1 バイトずつ増える)。
- **RTC がある系列では、`time()` を RTC から読む。** `settimeofday()` は RTC に書く。リセットやスタンバイをまたいで時刻が残る(電源か VBAT がある間)。RTC の無い系列は今のまま。

### 4.3 休止の調停

段階(ESP32 と意味を合わせる):

| 段 | CH32 の動作 | RAM | 起きたあと | ESP32 で近いもの |
|---|---|---|---|---|
| idle | WFI。クロックは全部動く | 残る | 次の割り込みで続きから | (自動の CPU 待ち) |
| 浅い休止 | ストップ。クロックが止まる | 残る | 呼んだ関数から戻る | light sleep |
| 深い休止 | スタンバイ | 消える(V30x と L103 は一部を残せる。BKP は残る) | リセットから | deep sleep |

案(名前は仮):
- `CH32RV.enableTimerWakeup(us)`、`CH32RV.enablePinWakeup(pin, level)`、`CH32RV.lightSleep()`(結果を返す)、`CH32RV.deepSleep()`(戻らない)、`CH32RV.wakeupCause()`。
- **自動では休止しない。** `loop()` が空いたことを、休止してよいことと同じにしない(決定 G5)。利用者が明示的に呼ぶ。
- **`delay()` の中で WFI を使うかは別に決める。** クロックは止まらないので、仕組みの上の意味は変わらない。ただし、裏の仕事の実行は、次の割り込み(1 ms 以内)まで遅れる。
- **休止の参加者。** 状態を持つドライバ(Serial、USB、Network、AdcStream、入力捕捉など)は、`begin()` で休止の参加者を登録する(service と同じく、表を持たない連結リストにする)。`lightSleep()` は参加者に順に準備を求める。誰かが Busy なら、休止せずに理由を返す。例: 送信中の UART は、送り終わるまで Busy を返す。進行中の I/O を勝手に捨てない(EXP-06 の模型の結論)。
  - 起きたら、コアがクロックを戻し、`millis()` を直し(4.2)、参加者に再開を求める。
- **利用者の仕事は、休止の判断に入れない。** 休止を呼ぶ前に、利用者が自分の仕事を片付ける(A の形)。`Deadline` の残りで休止の長さを決める書き方を、例で示す(`lightSleep()` の前に `enableTimerWakeup(deadline.remaining() * 1000)`)。
- **WDT との関係。** IWDG は休止中も動く。休止の長さが WDT の時間を越えるときは、休止せずに理由を返す案。裏で起きて WDT に餌をやる形は、隠れた進行になるので採らない。
- **PVD(電圧低下)。** 起床の要因と、`CH32RV` の状態として出す。callback が要るなら `deliverEvents()` で配る。

起床の手段(系列ごと):

| 手段 | 系列 |
|---|---|
| 端子(EXTI) | 全系列 |
| AWU(LSI の周期) | V003、V00x、M030、X035 |
| RTC のアラーム | V103、V20x、V205、V30x、V4x7、L103、X315、H41x |
| LPTIM | L103、H41x |
| PVD | M030 以外 |

周辺の表の AWU の行は、X035 にしか印が無い。V003、V00x、M030 の AWU は PWR のレジスタの中にあるので、表の生成で拾えていない。表を直す。

### 4.4 資源の所有

| 資源 | 今 | 案 |
|---|---|---|
| TIM | リース(timer-design) | 入力捕捉・エンコーダ・TIM-01 は `TryAcquire` で借り、借りられなければ `begin()` が false。**手放したときに SMCFGR(スレーブモード)が消えない**ので、コアの `stop_hardware()` で消す(実験で見つけた) |
| ADC | 規則なし(AdcStream の動作中は「`analogRead()` を使わないこと」と書いてあるだけ) | TIM と同じリースにする。`analogRead()` と `touchRead()` は短く借りて返す。AdcStream は持ち続ける。借りられなければ `analogRead()` は 0 など、決まった値を返す |
| EXTI の線 | `attachInterrupt()` と SPI スレーブの CS が使う | 1 本に 1 つの持ち主。端子での起床も、同じ線を使う。GPIO 以外の線(RTC のアラーム、PVD、USB の起床)はコアが持つ |
| RTC と BKP | 無い | コアが持つ(`time()` の元)。BKP の一部を、コアの印(RTC を合わせたか)に使う。残りを利用者に出すかは相談 |
| フラッシュ | H417 の DFU が使う | 永続化の領域はリンカーで確保する(persistence-spec) |
| 休止をまたぐ RAM | 無い | ESP32 の `RTC_DATA_ATTR` に当たる印を、ハードが RAM を残せる系列(V30x、L103。V20x は要確認)だけで出すかは相談 |

## 5. 項目ごとの形

### 5.1 休止と起床

4.3 のとおり。置き場所はコアの `CH32RV`。系列で違うのは、ストップに入る手順と、クロックの戻し方と、起床の手段だけにする。

E1・E3 の結果(2026-10-28。V003 と X035 は AWU、V307 は RTC のアラームで起こした。PC 側で行の届いた時刻を記録):

| | V003 | X035 | V307 |
|---|---|---|---|
| RAM が残り、続きから戻る深い休止 | 「スタンバイ」(PDDS=1)。ストップは無い | ストップ(PDDS=0)とスタンバイ(PDDS=1)の両方 | ストップ |
| リセットから戻る深い休止 | 無い | 無い | スタンバイ(RAM は消え、BKP と RTC は残る) |
| 休止の間の `millis()` | 止まる | 止まる | 止まる(RTC は進む) |
| 起きた直後のクロック | 変わらない(HSI のまま) | 変わらない | HSI に戻る。コアの SysTick の見張りが 5 ms 以内に PLL へ戻した |
| 起こす時間の正確さ | LSI で 1.5 秒が 1.7 秒(13 % 遅い) | HSI/1024 で 1.52〜1.57 秒 | RTC(LSI 約 37 kHz) |
| IWDG | 休止中も動き、リセットした | 同じ(X035 の IWDG は HSI/1024 で、休止中も止まらない) | 同じ |
| GPIO の出力 | 保たれた | 保たれた | — |

分かったこと:
- **段は「スタンバイ」「ストップ」の名前でなく、RAM が残るかで決める。** 浅い休止(`lightSleep()`)は、RAM が残る中でいちばん深いモード(V003・X035 はスタンバイ、V307 はストップ)。V003・X035 にはリセットから戻るモードが無い。
- **WFI は、AWU / アラームが来るまで繰り返す。** V003 では、休止の直前に入った別の割り込みで 1 回目の WFI がすぐ戻った。
- **クロックの戻し方は、今の見張り(`ch32rv_clock_is_ours()` → `SystemInit()`)で足りる。** ただし、起きてから最初の SysTick までは HSI のまま。休止から戻る関数の中で、すぐに戻すほうがよい。
- **経過時間の正確さは、時計しだい。** RTC は秒単位で正確。AWU は LSI がずれるので、`millis()` を進めるなら、入る前に LSI を HSI で測っておく(または、進めずに世代を進める)。
- **WDT は休止中も動く。** 休止の長さが WDT の時間を越えるときは断る、という 4.3 の案のとおりにする。
- **IWDG は止められない**(2026-10-28、V307 と V003)。止めるキーが無く、LSI を切っても(LSION=0)、キーに 0 を書いても、600 ms でリセットした。止まるのはリセットのときだけ。できるのは時間を延ばすことで、分周と再読み込みを最大にすると V307 は 28.8 秒、V003 は 9.2 秒になった。オプションバイトにも、STM32 の新しい系列にある「休止中は止める」ビット(IWDG_STOP / IWDG_STDBY)は無い(IWDG_SW と STOPRST だけ)。コアの中で IWDG を始めるのは `CH32RV.wdtEnable()` だけ。
- RTC の扱いの癖: BDCTLR は、RTCSEL と RTCEN を 1 回で書くと RTCEN が残らない(RTCSEL を書いてから、RTCEN を別に立てる)。起床の理由(PWR_CSR)は、PWR のクロックを入れてから読む。

### 5.2 時計(RTC と BKP)

- `time()` / `settimeofday()` の裏に入れる(4.2)。独自の RTC クラスは作らない(ESP32 と同じく POSIX の時刻関数で扱う)。
- アラームは、休止からの起床(`enableTimerWakeup()`)の手段として使う。利用者に「何時に起こす」を出すかは後で決める。
- RTC のクロック源は、基板しだい(32.768 kHz の水晶 LSE があるか)。メニューで `RTC Clock: LSI / LSE` を選ぶ案。LSI は数 % ずれるので、時刻を保つ用途には LSE を勧める。

### 5.3 永続化

persistence-spec の 3 層(raw、領域、EEPROM)と、その「決めてほしいこと」6 つのとおり。ほかの項目との接点は 2 つ。
- CPU が止まる系列での、`millis()` と通信への影響(4.2、4.5)。
- 休止の参加者にはならない。書き込みは呼び出しの中で終わるため。

### 5.4 入力捕捉とエンコーダ

V307 で実験した(TIM3、PA6 / PA7。刺激は同じ端子の GPIO、`tone()`、Servo):
- PWM 入力モード(TI1 から IC1 と IC2、スレーブのリセットモード)で、周期と High の時間が割り込み無しで取れた。5 kHz で 19201 / 9595 カウント(96 MHz)、Servo の 1500 µs で 999 カウント(1.5 µs の刻み)。
- タイマーのクロックは F_CPU と同じ。
- 端子が止まると、CC1IF が立たない。それで「新しい周期が無い」と分かる。周期が測れる範囲より長いと、更新のフラグ(URS=1 で桁あふれだけ)で分かる。
- エンコーダの x4 / x2 は、TIM1〜4 で正しく数えた。
- 端子を GPIO の出力にしたままでも、タイマーは端子のレベルを見る(V307)。配線なしの自己試験ができる。端子ごとに AF を選ぶ系列(V205、X315、H417)は未確認。
- 分周の値は、更新イベント(UG)を出すまで効かない。コアの `ch32TimerApplyBase()` は UG を出すので問題ない。
- **カウンタを止めたまま UG を出しても、カウンタは 0 に戻らない**(分周の値は入る)。V307 と L103 の 16 / 32 ビットのタイマーで確かめた。STM32 とは違う。`ch32TimerApplyBase()` はこれを当てにしていたので、前の持ち主の値が新しい周期より大きいと、カウンタの端まで回った。L103 の TIM4(32 ビット)では `tone()` の音を上げると数分鳴らなかった。コアでカウンタに 0 を書くように直した。errata への追加は data セッションに頼んだ。

実装(2026-10-28): ライブラリ `CH32RVTimerInput`(`CH32RVPulseCapture`、`CH32RVEncoder`)。V003、V006、V103、V203、V205、V307、L103、X035、X315、H417 で、配線なしの自己試験(同じ端子を GPIO・`tone()`・Servo で動かす)が全項目通った。端子ごとに AF を選ぶ系列(V205、X315、H417)でも、GPIO の出力にした端子をタイマーが読んだ。
- `stalled()` は「桁あふれが起きてから、`read()` が周期を返すまで true」にした。`minHz` より少しだけ遅い信号では、桁あふれと立ち上がりが交互に来るため、フラグだけでは止まったのか遅いのか分からない。
- チャネルの無い端子のエンコーダは、まず案 b(ハードの端子だけ)で出した。案 a は API を変えずに後から足せる。
- 手放したタイマーにスレーブモード(SMCFGR)が残る問題は、コアの `stop_hardware()` で消すように直した。

形の案:
- ライブラリ `CH32RVTimerInput`。周期・パルス幅の測定と、エンコーダの 2 つのクラス。
- 端子は、そのタイマーの CH1 / CH2(PWM の表の既定の経路)。タイマーごと(チャネル 0)に借りる。
- 測定は `read()` で最新の 1 周期を取る。割り込みは使わない。測れる最も低い周波数を `begin()` で指定し、それで分解能が決まる。
- エンコーダは ESP32Encoder と同じ名前(`attachFullQuad()`、`attachHalfQuad()`、`getCount()`(64 ビット)、`clearCount()`、`setCount()`、`pauseCount()`、`resumeCount()`、`setFilter()`)。16 ビットを越える分は、更新割り込みで内部で数える。利用者の callback は無い。
- **タイマーのチャネルが無い端子をどうするかは相談。** 案 a: 同じクラスで、EXTI の割り込みで数えるソフトの方式に切り替える。案 b: ハードの端子だけにして、`begin()` が false を返す。測定のほうは、今ある `pulseIn()`(ソフト)が代わりになる。

### 5.5 HSE

4.1 のとおり。

E5 の結果(2026-10-28、ベンチの基板。HSEON から HSERDY までと、SYSCLK を HSE にして UART の分周で読めた周波数):

| 基板 | HSE | 立ち上がり | 周波数 |
|---|---|---|---|
| V307(VCT6) | あり | 2.5 ms | 8 MHz |
| V203(C8T6) | あり | 1.3 ms | 8 MHz |
| L103(C8T6) | あり | 2.2 ms | 8 MHz |
| V003(F4P6) | あり | 2.3 ms | 24 MHz(25 MHz の行も読めた。UART の許容の内) |
| V006(K8U6) | あり | 1.6 ms | 24 MHz(同上) |
| H417(QEU6) | あり | 0.9 ms | 25 MHz(Ethernet が 25 MHz の前提で動いている) |
| V103(R8T6) | あり | 1.0 ms | 未確認(UART が読めない Link) |
| V205(RCT6) | あり | 1.6 ms | 未確認(UART が Link に無い) |
| X315(MCU6) | あり | 0.9 ms | 未確認(同上) |
| X035(C8T6) | なし | — | X035 に HSE は無い |

分かったこと:
- 立ち上がりは 1〜2.5 ms。ストップからの起床に、この時間が加わる。
- 基板によって 8 / 24 / 25 MHz と違う。メニューで周波数を選ぶ形が要る。
- **コアの SysTick は、クロックが自分の構成と違うとすぐに `SystemInit()` で戻す**(デバッガ対策、`ch32rv_clock_is_ours()`)。HSE の構成も「自分の構成」として認める生成が要る。`SystemInit()` は HSE を切る(Ethernet の注記)ので、HSE を選んだときは切らないようにする。
- 周波数を間違えて選ぶと、UART も `millis()` もずれるだけで気づきにくい。**起動時に HSE を HSI と比べて、メニューの値から大きく外れていたら HSI に戻り、`clockSource()` で知らせる**案を足す(比べる方法は、タイマーの入力捕捉か、決まった数のループの時間)。

### 5.6 TouchKey

- `touchRead(pin)` を ESP32 と同じ意味にする(生の数値を返す。正規化しない)。触ったときに増えるか減るかは系列ごとに文書にする(ESP32 も、ESP32 と S2 / S3 で逆)。
- 対象は TKey のある 8 系列(V00x、V103、V20x、V205、V30x、L103、X035、H41x)。無い系列は 0 を返す。
- ADC を短く借りる(4.4)。1 回の測定時間を実測して、`analogRead()` と同じ「短い即時の操作」と言えるかを確かめる。
- しきい値で割り込む `touchAttachInterrupt()` は後にする。ADC のアナログウォッチドッグで作れるかを見てから。

## 6. 依存と順番(案)

1. **共通の土台。** TIM の SMCFGR の後始末、ADC のリース、`timeDomain()`、休止の参加者の連結リスト、`CH32RV_HSE_HZ`。どれも小さく、使わなければ 0 B。
2. **入力捕捉・エンコーダ。** 共通の土台のうち TIM の後始末だけに依存する。
3. **HSE。** 休止からの復帰が、クロックの構成に依存するため、休止より先に作る。
4. **休止と時計。** 一緒に作る。
5. **TouchKey。** ADC のリースに依存する。
6. **永続化。** persistence-spec の 6 問への答えが出てから。フラッシュの書き込み中の `millis()` の実験は、4 と共有する。

## 8. 決まったこと(2026-10-28、実験のあとの相談)

- **`deepSleep()`:** リセットから戻るモードが無い系列(V003、X035)では、いちばん深い休止で眠り、起きたらソフトで再起動する。どの系列でも「起きたら `setup()` から」という同じ意味にする。
- **休止の間の `millis()`:** 測れた分だけ進める。RTC のある系列は RTC で、AWU の系列は入る前に LSI を HSI で測っておく。測れない起床(時計の無い起床)では進めずに、時刻の世代を進める。
- **WDT:** 止められないので、`lightSleep()` の間は止まっているように見せる(Zephyr の `WDT_OPT_PAUSE_IN_SLEEP`、STM32 の IWDG_STOP と同じ意味)。休止の直前に WDT の時間を最大に延ばし、それより長い休止は手前で起きて餌だけやってまた眠る(コアの数命令だけ。裏の仕事も利用者の関数も動かない)。起きたら利用者の時間に戻して餌をやる。WDT が有効なときの `deepSleep()` は、同じ方法で眠ってから再起動する(V307 のスタンバイの間は餌をやれないため)。WDT が無効なら本物のスタンバイを使う。
- 実装の順番は任された。6 章のとおり HSE から。

## 9. 決めてほしいこと(最初の案のときのもの)

1. この進め方(共通の土台 → 個別)と、6 の順番でよいか。
2. Ticker は作らずに `Period` を案内し、TIM-01 は「割り込みで合図」に限る(3)。
3. 休止の 3 つの段と、自動では休止しないこと。`delay()` の中で WFI を使うか(4.3)。
4. 休止の参加者が Busy なら休止しない(強制しない)形(4.3)。
5. 経過が分からないときは、`millis()` を進めずに世代を進める。`Deadline` に世代を持たせるか(4.2)。
6. RTC のある系列で、`time()` を RTC に切り替える。RTC のクロック源をメニューにする(4.2、5.2)。
7. HSE の周波数の正本をメニューにし、ライブラリの `hseHz` / `setHseFrequency()` をそれに合わせる(4.1)。
8. ADC を TIM と同じリースにする(4.4)。
9. タイマーのチャネルが無い端子のエンコーダ(案 a / b、5.4)。
10. BKP の残りと、休止をまたぐ RAM の印を利用者に出すか(4.4)。
