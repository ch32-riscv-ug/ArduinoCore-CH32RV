# 未実装の周辺の洗い直し（2026-10-28）

[周辺機能表](peripheral-support.ja.md)で「未実装」「対象外」「一部実装」の機能を、ゼロから「実装したほうがよい」「不要そう」に分けたものです。

周辺の一覧は、次の 2 つの出典を合わせて作り直しました。漏れを防ぐためです。
- EVT の例（例の中のサブフォルダを含む）。
- ch32-device-data の register_blocks.csv。

device-data の漏れ（PIOC、H417 の HSEM / IPC、V103 の USB）と疑わしい行（V103 の DAC、V205 の LVDS、V20x の OSC）は、data セッションに問い合わせています。

## 判断の物差し

どの項目にも、同じ 6 つを当てました。

1. **Arduino の API**: 標準の API や定番のライブラリがあるか。ESP32 の API に合わせられるか。
2. **ファミリーの数**: 何ファミリーのシリコンにあるか（12 ファミリー中）。
3. **使い道**: 利用者が普通に必要とするか。
4. **ほかへの効き**: ベンチの試験や、ほかのコア機能に要るか。
5. **手間**: 大きなスタックや、WCH のバイナリのライブラリが要るか。
6. **置き場所**: コアの公開 API か、ライブラリで足りるか。

## A. 実装したほうがよい（優先して）

**2026-10-29: A はすべて入った。** 休止（6ce04f8c、AWU の系列）と RTC・RTC の系列の休止（ef6a4acf）、フラッシュの永続化（`ch32rv_flash.h`、[flash-store](flash-store.ja.md)）、タイマーの入力捕捉とエンコーダ（CH32RVTimerInput、758d73d4）、HSE（Clock Source のメニュー、d99f8979）、TouchKey（`touchRead()`、718996f4）。系列ごとの範囲は [周辺機能表](peripheral-support.ja.md)。

| 機能 | ファミリー | 理由 | 置き場所の案 |
|---|---|---|---|
| PWR（スリープ・ストップ・スタンバイと起床。AWU を含む） | 12 | 電池で動かす用途の基本。ESP32 の `esp_sleep_*` に合わせられる。起床の手段（EXTI・RTC のアラーム・LPTIM・AWU）とまとめて設計する | コア（ESP32 に合わせた API） |
| RTC（BKP を含む） | 8 | リセットをまたいで時刻を保つ、アラームで起こす。今の `settimeofday()` / `time()` と同じ時計につなぐ | コア |
| フラッシュの永続化（EEPROM / Preferences） | 12 | 設定の保存は定番の需要。設計は docs/persistence-spec.ja.md で進行中 | コア・ライブラリ |
| タイマーの入力捕捉とエンコーダ | 12 | 周波数・パルス幅の測定、ロータリーエンコーダ。今は `pulseIn()` がソフトで数えるだけ | ライブラリ |
| HSE（外付けの水晶） | 12 | 正確なクロック（UART・USB・時刻）。USBHS（V30x）はライブラリが自分で使っているだけで、CPU Clock では選べない | コア（CPU Clock のメニュー） |
| TouchKey | 7 | ESP32 の `touchRead()` に合わせられる。ボタンを部品なしで作れる | コア（`touchRead()`） |

## B. 実装したほうがよい（後で）

| 機能 | ファミリー | 理由 | 置き場所の案 |
|---|---|---|---|
| CAN（L103 は CAN FD） | 6 | ArduinoCore-API に `HardwareCAN` がある。ただしバスにつなぐには外付けのトランシーバー（L103 の FD は FD 対応のもの）と終端が要り、常設ベンチの組み方も重くなるので後にする（2026-10-28）。作るときは、まず内部のループバックとサイレントモードで 1 台で試せる範囲から | コア（`HardwareCAN`） |
| I2S（SAI を含む） | 3（V30x・V4x7・H41x） | ESP32 の ESP_I2S に合わせた音声の入出力 | ライブラリ |
| SD カード（SDIO / SDMMC）とファイルシステム | 3 | データの記録。まず SPI の SD で始め、SDIO は速さが要るとき | ライブラリ |
| ADC のトリガ（タイマー）・アナログウォッチドッグ・デュアル | 12 / 12 / 5 | 遅い一定のレートでの取り込み（AdcStream の残り）、しきい値の割込み | ライブラリ（CH32RVAdcStream の拡張） |
| 相補 PWM・デッドタイム・ワンパルス | 12 | モーターと電源の制御 | ライブラリ |
| ARGB（WS2812 など） | 2（ハード）、12（SPI / PIOC で代える） | NeoPixel は利用者に人気。Adafruit_NeoPixel と同じ使い方にしたい | ライブラリ |
| 比較器と OPA | 7 | アナログの前段（PGA）と、比較器の割込み・ブレーキ・起床 | ライブラリ |
| PVD（電圧低下の検出） | 11 | 電池の低下を知らせる。PWR と一緒に設計する | コア（PWR と同じ所） |
| RNG の公開 API | 3 | ESP32 の `esp_random()` と `randomSeed()` の種。中身は既にある | コア |
| CRC の公開 API | 7 | 保存データの検査。手間が小さい | コア |
| MCO（クロックの出力） | 12 | ベンチでクロックを外から測れる（試験の価値）。手間が小さい | コア |
| RAM での実行の印 | 3（EVT の例）、ほぼ全部 | タイミングに厳しい処理や、フラッシュの書き換え中の処理。crt0 の仕組みは既にある | コア（関数に付ける印） |
| WWDG | 12 | 手間は小さいが、IWDG で足りる場面が多い | コア |
| 2 つ目のコア（H417 の V5F、HSEM・IPC） | 1 | H417 の性能を使い切るため。設計の実験を進めている | コア・ライブラリ |
| オプションバイト | 12 | リセット端子（Reset Pin）と Flash / RAM Split は、ボードメニューで選び、起動時にコアが合わせる形にした（ch32rv_option_user.c）。ほかの項目（IWDG の起動、STOP / STANDBY のリセット、START_MODE、ISP の許可、読み出しの保護など）は、メニュー・API・ch32rv のどれにするかを洗い出す | コア（メニュー）、残りは未定 |
| 外部メモリ（QSPI・PSRAM・FSMC / FMC） | 4 | 大きなデータ。基板に部品が要る | ライブラリ |
| DVP・LTDC・GPHA（カメラ・表示・2D） | 3 | 画像の用途。重く、基板に部品が要る | ライブラリ |
| ECDC（AES / SM4） | 1 | TLS（mbedTLS）の暗号を速くする | Network の中 |
| USB の HS host と SS host | 5 / 1 | HS host は今は無い。SS host は TODO に記録済み（H417） | ライブラリ（CH32RVUsbHost） |

## C. 不要そう（今は作らない）

| 機能 | ファミリー | 理由 |
|---|---|---|
| BLE（V208） | 1 | WCH のバイナリのスタックが要り、対応がこのファミリーだけ。必要になれば別のライブラリとして検討する |
| SWPMI | 1 | SIM カードとの単線の通信。用途が狭い |
| UHSIF・SerDes | 1 | 専用の高速の接続で、相手の機器が要る |
| DFSDM | 1 | 外付けの ΣΔ 変調器（マイクなど）向け。音声をやるときに I2S と合わせて考え直す |
| I3C | 2 | 対応する部品がまだ少ない |
| PMP（メモリ保護） | 7 | Arduino の使い方では効き目が小さい。RTOS を載せるなら考え直す |
| DMA の公開 API | 12 | ライブラリの中（LogicCapture・HsAdc・AdcStream）で使う。利用者に直接は出さない |
| RTOS の移植（FreeRTOS など） | 9 | TaskKit / SyncKit の実行モデルで足りる |
| LVDS（V205） | 1 | 用途が未確認。device-data の答えを待って判断し直す |
