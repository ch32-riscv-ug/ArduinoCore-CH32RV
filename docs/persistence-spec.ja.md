## 範囲

対象にするもの:
1. 内蔵フラッシュを読み、消し、書く関数(FEATURE_CANDIDATES の SYS-02)。
2. フラッシュの末尾に、保存のための領域を確保すること。スケッチを書き込み直しても、その中身を残すこと。
3. 少量の設定を保存するライブラリ(SYS-01)。

対象にしないもの: ファイルシステム(STO-01〜04)、ファームウェアの自己更新(UPD-01、02)、外付けの EEPROM や Flash、電源断に備えた保持 RAM やバックアップレジスタ。

## 全体の形(案)

3 つの層に分ける。下の層は、上の層がなくても使える。

| 層 | 置き場所 | 中身 | 使わないときの費用 |
|---|---|---|---|
| 1. raw | コア(`ch32rv_flash.h`) | 単位の問い合わせ、消去、書き込み、読み出し | 0 B(呼ばなければリンクされない) |
| 2. 領域 | コアのリンカーとライブラリ | フラッシュの末尾の確保。書き込み直しで残す | 0 B(確保しなければ) |
| 3. EEPROM | ライブラリ(`EEPROM.h`) | Arduino の EEPROM の API。2 つの面を交互に書く | 0 B(include しなければ) |

キーと値の保存(ESP32 の Preferences に当たるもの)とファイルシステムは、この 3 層の上に後から足せる形にしておく。今回は作らない(「比べた案」を参照)。

## 1. raw の関数

H417 だけにある今の `ch32rv_flash.h` を、全系列に広げる。

```c
uint32_t ch32rv_flash_size(void);          /* この型番のコード用フラッシュの大きさ */
uint32_t ch32rv_flash_erase_size(void);    /* 一番小さい消去の単位(高速の消去があればその単位) */
uint32_t ch32rv_flash_write_size(void);    /* 書き込みのページ */
bool ch32rv_flash_rewritable(void);        /* 消さずに 0 の向きに書き足せるか */
ch32rv_flash_status ch32rv_flash_erase(uint32_t offset, uint32_t length);
ch32rv_flash_status ch32rv_flash_write(uint32_t offset, const void *data, uint32_t length);
/* 読み出しは普通のメモリとして読む(アドレスは ch32rv_flash_address(offset)) */
```

- 単位の値は、device-data から variant に生成する。関数が返すので、コアに条件付きの define は増やさない。
- 消去する範囲は、`erase_size` の倍数でなければならない。書き込みの範囲は、`write_size` の倍数でなければならない。合わないときは、何もせずに `CH32RV_FLASH_ERR_ALIGN` を返す。2 バイト単位の書き込みは出さない(256 B で 270 ms かかり、使いどころがない)。
- 書き込んだあとに読み直して、書いた値と比べる。違えば `CH32RV_FLASH_ERR_VERIFY` を返す。
- ほかの戻り値: `OK`、`ERR_RANGE`(フラッシュの外、またはスケッチ自身の領域)、`ERR_PROTECT`(書き込み保護)、`ERR_TIMEOUT`。
- スケッチ自身の領域の消去は、H417 の DFU のように、自分を書き換える用途(UPD-01)だけに許す。どう区別するかは、実装のときに決める。
- 処理中に CPU が止まる系列(V003、V103、X035、L103、ほかは未測定)では、関数から戻るまで割り込みが入らない。
  - SysTick の割り込みも 1 回しか通らないので、millis() が遅れる(X035 で 3 ms の消去のたびに約 2 ms)。
  - 案: 処理の前後で SysTick のカウンタの差を読み、足りない ms を足す。SysTick が処理の間も数え続けるかは、まだ確かめていない(TIM2 は数え続けた)。
- RAM で動かすこと(`.highcode`)は求めない。止まる系列では、RAM で動かしても割り込みが入らないので、得るものがない。そのためには `.highcode` の不具合(V003 以外で写されない)も先に直す必要がある。

## 2. 保存の領域

### 確保の仕方

- ライブラリ(またはスケッチ)が、大きさを決めた配列を `.ch32rv_store` に置く。リンカーは、それをフラッシュの末尾に寄せて置く(flash-raw で試した形)。
- 何も置かなければ、確保は 0 B のまま。メニューは要らない。
- 置く場所は、選んだ型番のフラッシュの末尾。大きさが同じなら、ビルドが変わっても同じ場所になる。
- 注意: 型番のメニューを ANY から型番に変えると、末尾が動くことがある(V006 は ANY が 16 KB、最大 62 KB)。そのときは、前の中身を見つけられない。これは文書に書いておく。
- Arduino が表示する使用量には、確保した分が入らない。案: 確保した大きさを、ビルドの最後に 1 行出す。
- 確保した大きさに、ほかのコードやデータが重なれば、リンクで止まる(flash-raw で確かめた)。
- 一つのスケッチに、確保できる領域は一つにする。複数のライブラリが同じ領域を使うときの所有の規則は、今回は作らない。EEPROM のライブラリだけが使う。

### 書き込み直しで残す

| 経路 | 今 | 案 |
|---|---|---|
| WCH-Link / OEP(`ch32rv flash`) | 既定 `--erase keep-store` で残る(ch32rv 0.25)。Erase Flash の All Flash を選ぶと消える | — |
| H417 の DFU(`boot dfu flash`) | 残る(確かめた) | そのまま |
| 工場の ISP(`isp flash`) | 未測定 | 測ってから決める。残せない経路は、その旨を文書に書く |
| HID のブートローダー | 未測定 | 同じ |

- 全部を消したいときのために、ボードメニュー `Erase Flash: Sketch Only (default) / All Flash` を足す案。表示は英語にする。

## 3. EEPROM のライブラリ

### API

Arduino の EEPROM の API に、フラッシュ向けの `begin(size)` と `commit()` を足したもの。RP2040 や ESP8266 の Arduino のコアも、同じ形をとっている。

```cpp
#include <EEPROM.h>
EEPROM.begin(256);          // 使う大きさ。保存してあった中身を RAM に読む
EEPROM.read(addr); EEPROM.write(addr, v); EEPROM.update(addr, v);
EEPROM.get(addr, obj); EEPROM.put(addr, obj); EEPROM[addr];
EEPROM.length();
bool ok = EEPROM.commit();  // RAM の中身をフラッシュへ。変わっていなければ何もしない
EEPROM.end();               // commit してから RAM を返す
EEPROM.status();            // begin の結果: Loaded / Empty / Corrupt / TooLarge
```

- 中身は RAM に全部持つ。RAM は `size` バイト使う。V003(RAM 2 KB)でも、小さい大きさなら使える。
- write() はフラッシュに書かない。commit() で初めて書く。AVR の EEPROM と違うので、文書と例で示す。
- 保存の最大の大きさは「1 面の大きさ − 16 B(見出し)」。`begin()` にそれより大きい値を渡すと、`TooLarge` にして使えなくする。

### 形式

- 同じ大きさの面を 2 つ置き、交互に書く。
- 面の先頭 16 B に見出しを置く。中身は magic、世代(32 bit)、長さ、版、CRC32。CRC は見出しの前の 12 B と中身の全体にかける。
- `begin()` は、CRC が合う面のうち、世代が大きいほうを読む。同じ世代が 2 つあれば `Corrupt` にする。
- `commit()` の手順は次のとおり。
  1. 使っていないほうの面を消す。
  2. 中身を書く。ページは後ろから順に書き、見出しを含む先頭のページを最後に書く。
  3. 読み直して確かめる。
  - 先頭のページを最後に書くので、完了印のために別のページを使わずに済む。消さずに書き直せない系列でも使える。
- 中身がないページは書かない(消したままにする)。
- 読むたびに値が変わる語に備えて、`begin()` は CRC を 2 回計算し、両方合ったときだけ「合った」とする。

### 電源断のときに約束すること

- `commit()` の途中で電源が切れても、次の `begin()` では、前に commit した中身か、新しい中身のどちらかが読める。
- 約束しないこと:
  - 2 つの面が両方壊れた場合。commit の途中でもう一方の面が壊れることは、今の形式では起きないはず。
  - CRC が偶然合う場合。
  - 寿命を超えた書き換え。
  - 電圧の低い状態での書き込み。
- 最初の commit の途中で切れたときは、`Empty` になる。
- 上の約束は、実機の電源断の試験(下の「実装の前に測ること」)で確かめてから文書に書く。

### 系列ごとの確保と commit の時間(案)

面の大きさは、系列ごとに 1 つの既定値にする。消去が速くなる大きさを選んだ。commit の時間は、flash-raw の数字から見積もった値で、まだ測っていない。

| 系列 | 1 面 | 確保(2 面) | 保存できる最大 | commit(1 KB を書くとき) | commit(1 面いっぱい) | CPU が止まる | commit の回数の目安(寿命 × 2) |
|---|---|---|---|---|---|---|---|
| V003 | 128 B(64 B × 2) | 256 B | 112 B | — | 約 12 ms | はい | 2 万回 |
| V103 | 1 KB | 2 KB | 1008 B | 約 48 ms | 約 48 ms | はい | 2 万回 |
| X035 | 1 KB | 2 KB | 1008 B | 約 10 ms | 約 10 ms | はい | 60 万回 |
| L103(8 MHz) | 2 KB | 4 KB | 2032 B | 約 16 ms | 約 26 ms | はい | 60 万回 |
| V307 | 4 KB | 8 KB | 4080 B | 約 23 ms | 約 42 ms | いいえ | 2 万回 |
| H417 | 8 KB | 16 KB | 8176 B | 約 5 ms | 約 24 ms | いいえ | 10 万回 |
| ほかの系列 | 単位から同じ規則で決める | | | 未測定 | 未測定 | 未測定 | |

- 見積もりは「消去 1 回 + 書くページの数 × (ページの書き込み + バッファへの読み込み)」。

- 回数の目安は、2 つの面に分けて消すので、寿命の 2 倍とした。
- 変わっていなければ書かないので、同じ値を何度 commit しても減らない。

### 大きさ(見積もり)

- EXP-04 の C++ 試作(2 面、CRC、LTO あり)は、V003 で 1,764 B、X035 で 1,716 B だった。これは試験用の入口と仮の媒体も含んだ値で、本物のフラッシュの処理は含まない。
- 実装したら、空のスケッチとの差を V003、X035、V307 で測る。

## 比べた案

同じ物差しで並べた。大きさの数字は上の記録から取った。○ は条件を満たす、× は満たさない、△ は条件付き。

| 案 | 確保の最小 | RAM | コード | 電源断 | 消さずに書き直せない系列 | V003(16 KB / 2 KB) |
|---|---|---|---|---|---|---|
| raw の関数だけ(利用者が全部やる) | 0 | 0 | 小さい | 利用者しだい | 利用者しだい | ○ |
| EEPROM、1 面を上書き | 1 単位 | size | 小さい | ×(消してから書くまでに旧値を失う) | ○ | ○ |
| **EEPROM、2 面を交互に(この案)** | 2 単位 | size | EXP-04 で 1.7 KB 前後(試験の入口込み) | ○(旧値か新値) | ○ | ○(最大 112 B) |
| 1 面に追記するログ | 1 単位 | 小さい | 中くらい | △ | ×(書き直せない) | ○ |
| キーと値(複数ページのログ) | 3 単位以上 | 索引しだい | 大きい | ○(作り方しだい) | △(1 件に 1 ページ以上) | △ |
| littlefs | 数ブロック | 1.8 KB | 16 KB | ○(PC 上で 0 件) | ○ | × |

2 面の EEPROM を推す理由:
- Arduino の標準の API なので、EEPROM を使う既存のライブラリが動く。
- 全系列で同じ形式が使える。消さずに書き直せない系列でも使える。
- 電源断のときに、旧値か新値のどちらかが残る。
- 使わなければ費用は 0。RAM の量は、利用者が `begin()` に渡す大きさで決まる。

キーと値の保存は、EEPROM の中身の上に小さな形式を載せて作れる(RAM に全部あるので、コードが小さく済む)。必要になってから考える。

## 決めてほしいこと

1. この 3 層の形でよいか。特に、最初に作るのを EEPROM(2 面)にするか。
2. 面の大きさを系列ごとに固定するか、ボードメニュー(英語の表示、確保するバイト数を表示)で選べるようにするか。
3. raw の関数を、利用者に公開するか、コアとライブラリの中だけで使うか。
4. millis() の補正を入れるか(SysTick の確認が先)。
5. 型番のメニューを変えると、保存した中身を見つけられなくなる。これを文書に書くだけでよいか。

## 実装の前に測ること

- 未測定の系列(V00x、M030、V205、V20x、V407、X315)で: 単位、時間、CPU が止まるか、消さずに書き直せるか。
- 2 面の形式で、実機の電源断の試験(flash-raw の手順、各系列 30 回以上)。旧値か新値が残るか。
- 処理の間に SysTick が数え続けるか。millis() の補正の効果。
- CPU が止まる系列で、commit の間に USB(CDC)が切れないか。UART で受けたバイトを落とさないか(115200 bps では 87 µs に 1 バイト届く)。X035 は PC につながった台がベンチに無いので、その用意から。
- 書き込みの経路ごとに、保存の領域が残るか(ISP、HID)。
- 大きさ(空のスケッチとの差)を V003、X035、V307 で。

## 進め方(案)

1. raw の関数を全系列に広げ、未測定の系列を測る。
2. 領域の確保(リンカー)。
3. EEPROM のライブラリ。電源断の試験と大きさの測定をしてから、文書に約束を書く。
4. 必要になったら、キーと値の保存、内蔵フラッシュの上の littlefs(大きい系列だけ)。
