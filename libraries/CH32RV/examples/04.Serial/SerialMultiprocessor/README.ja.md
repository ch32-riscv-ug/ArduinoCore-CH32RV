# SerialMultiprocessor

[English](README.md)

1 本の UART の線に何台もつなぎ、アドレスで呼び分けます（USART のミュートモード、`setAddress()`）。呼ぶ側が
アドレスのフレームに続けてデータを送ると、そのアドレスのノードだけがデータを受け取ります。

## 必要なものと配線

同じスケッチを書いたボードを 2 台以上。1 台は `MY_ADDRESS` を 0（呼ぶ側）、ほかは 1、2、3 にします。呼ぶ側の TX を
全ノードの RX へ、GND 共通。ノードの TX はつなぎません。各ノードの LED（`LED_BUILTIN`、無ければ `A0` などの端子に
LED と抵抗）が点きます。

## 操作と期待する結果

電源を入れると、ノード 1、2、3 の LED が 0.5 秒ずつ順に点きます。呼ぶ側は毎回 3 台全部に値を送りますが、各ノードは
自分のアドレスの後のバイトしか受け取らないので、ほかのノード宛ての `'1'` では点きません。

## API と処理の流れ

`setAddress(a)`（0〜15）で、8N1 の語が 9 ビットになります。9 ビット目はアドレスのフレームで 1、データで 0 です。
受信側は、下位 4 ビットが自分のアドレスのアドレスフレームの後だけデータを受け取り、ほかのアドレスのフレームで
自分から黙ります。アドレスのフレーム自体は `read()` に来ません。`writeAddress(a)` はアドレスのフレームを 1 つ送ります
（それまでに `write()` したものが先に出ます）。`setAddress(-1)` で普通の UART に戻ります。

`mute()` は次に自分宛てのアドレスが来るまで受信を止めます。`setAddress()` を使わないときは、線が 1 フレームの間
静かになるまで止めます（メッセージの残りを読み飛ばす）。線が静かなときに呼んでもすぐ戻るので、メッセージの途中で呼びます。

パリティ付きの形式（8E1 など）と 5・6 データビットでは `setAddress()` が false を返します。9 ビット目がパリティの
場所だからです。`setRxBufferSize()` の DMA 受信とも併用できません（DMA がアドレスのフレームも読むため）。

## 改造するとき

ノードが返事をするなら、ノードの TX を開放ドレインにして（または 1 本ずつダイオードを挟んで）呼ぶ側の RX へまとめ、
呼ぶ側にも 0 番のアドレスで返します。RS485 のトランシーバーを挟むなら `setMode(UART_MODE_RS485_HALF_DUPLEX)` と
組み合わせられます。
