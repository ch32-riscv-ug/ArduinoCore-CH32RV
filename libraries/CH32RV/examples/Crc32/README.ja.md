# Crc32

[English](README.md)

`CH32RV.crc32()` でデータを検査します。CRC のハードウェアがある石では、それで計算する CRC-32 です。

## 必要なものと配線

UART モニタを用意します。

## 操作と期待する結果

起動すると、検査用の文字列 `123456789` が、1 回でも 2 つに分けても `0x376E6E7` になります。2 秒ごとにパケットを作って 1 ビット化けさせ、`packet damaged: CRC mismatch` と出ます。

## API と処理の流れ

`CH32RV.crc32(data, len)` は `len` バイトの CRC を返します。`CH32RV.crc32(data, len, crc)` は前の結果から続けるので、届いた順に検査できます。CRC は CRC-32/MPEG-2（多項式 0x04C11DB7、初期値 0xFFFFFFFF、ビットの反転なし、最後の XOR なし）で、CRC のハードウェア（V103、V20x、V205、V30x、V4x7、L103 / M103、X305 / X315、H41x）が計算するものです。ほかの石はソフトで同じ値を計算します。C の関数は `ch32rv_crc.h` の `ch32rv_crc32()` です。

## 改造するときの注意

zlib や Ethernet の CRC-32（同じ多項式を反転し、最後に XOR する。検査値は `0xCBF43926`）とは違います。そちらを決めているプロトコルには、別にソフトの CRC が要ります。CRC は偶然の化けを見つけるもので、意図した書き換えは防ぎません。
