# ResetReason

[English](README.md)

通常のリセットと、UART操作によるソフトウェアリセットを比較します。追加部品は不要です。

## 操作とAPI

端末を開いてボードをリセットし、`Reset reason`を読みます。小文字の`r`を送ると、`Serial.flush()`で送信完了を待ち、`CH32RV.restart()`で再起動します。次の起動ではソフトウェアリセットの理由を表示します。

`restart()`はチップをリセットし、呼び出し元へ戻りません。後に書いた処理で後始末はできません。`resetReasonName()`は表示用の名前です。プログラムで判定する場合は`resetReason()`と`CH32RV_RESET_*`を使います。同じ起動中に繰り返し読んでも、保持された同じ理由を返します。

この例では操作したときだけ再起動します。異常からの回復へ応用する場合も、`setup()`で無条件に再起動を繰り返さないようにします。誤配線や外部機器によるバスの保持は、MCUのリセットだけでは直りません。最初の表示を取り逃した場合は端末を開いてからリセットします。基板によってはUSB-UARTの制御線の変化でもリセットされます。

## 実行前の準備

ボードと正確なPart Numberを選び、スケッチの端子を回路図と照合します。ログはハードウェア`Serial`の115200 baud・8N1です。アダプタRXをボードTX、アダプタTXをボードRXへ接続し、GNDを共通にします。I/O電圧を合わせてください。基板のUSB端子だけでこのUARTが見えるとは限りません。

生成された`sketch.yaml`にビルドprofileがあります。ビルド成功は配線や実機動作の確認とは別です。[ビルド規則](../../../../docs/examples-build-rules.ja.md)と[書き込み経路](../../../../docs/upload-routes.ja.md)も参照してください。
