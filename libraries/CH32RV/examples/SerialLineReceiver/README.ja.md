# SerialLineReceiver

[English](README.md)

文字が届く間にもほかの処理へ戻り、固定長配列で一行ずつ受信します。Streamの行読み取り関数で待つ[SerialEcho](../SerialEcho/README.ja.md)との比較用です。

## 操作

端末の行末をLFまたはCRLFにします。`hello`を送ると`Line: hello`と返します。複数行の連続送信、空行、前後に空白のある行も試します。空白は残し、LF直前のCRだけを取り除きます。CRだけでは行が終わりません。テキスト向けの例なので、任意のバイナリは[SerialPacketReceiver](../SerialPacketReceiver/README.ja.md)で扱います。

LFの前までに最大31 byteを保持します。CRもあればこの長さに含みます。長すぎる入力はLFまで捨て、一度だけエラー表示します。後半の文字が別の正常な行として受理されないことを確認します。途中まで送って1秒より長く空けると、その部分をtimeoutで破棄し、後から届く文字で新しい行を始めます。

## APIと改造時の注意

`available()`でバッファ内の数を調べ、`read()`で1 byte取り出します。次の文字の到着を待つ読み取りは行いません。1回のloop()では最大16 byteを扱い、`millis()`の符号なし引き算で無通信時間を判定します。配列には`\0`用の1 byteを残し、正常な一行が完成したときだけ終端を書きます。

timeoutは処理したbyte間の空き時間であり、行全体の所要時間ではありません。長さは文字数ではなくbyte数なので、日本語等は複数byteを使います。メイン処理が遅いとUART側の受信バッファはあふれます。また、受信量を制限しても`Serial.print()`が待たなくなるわけではありません。連続した高速入力では返信を短くする・キューへ積むなどし、送信前に`availableForWrite()`も確認します。受信ループの後に、別の短い処理を追加できます。

## 実行前の準備

ボードと正確なPart Numberを選び、スケッチの端子を回路図と照合します。ログはハードウェア`Serial`の115200 baud・8N1です。アダプタRXをボードTX、アダプタTXをボードRXへ接続し、GNDを共通にします。I/O電圧を合わせてください。基板のUSB端子だけでこのUARTが見えるとは限りません。

生成された`sketch.yaml`にビルドprofileがあります。ビルド成功は配線や実機動作の確認とは別です。[ビルド規則](../../../../docs/examples-build-rules.ja.md)と[書き込み経路](../../../../docs/upload-routes.ja.md)も参照してください。
