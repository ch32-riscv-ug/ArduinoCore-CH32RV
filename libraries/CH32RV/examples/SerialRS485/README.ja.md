# SerialRS485

[English](README.md)

送信のたびにコアがドライバーの有効（DE）を切り替える RS485 のトランシーバー（MAX485、SP3485 など）で、1 秒ごとに
バスへ問い合わせ、答えを `Serial` に出します。

## 必要なものと配線

3.3 V の RS485 トランシーバー。DI を `Serial1` の TX、RO を `Serial1` の RX、DE と /RE をまとめて `DE_PIN`（スケッチでは
A1。どの端子でもよい）、A / B を終端のあるバスへ、GND 共通。`?\n` に 9600 8N1 で答える機器をバスに置きます。
答えは `Serial`（115200）に出ます。

## 操作と期待する結果

ボードが `RS485 ready` を出し、1 秒ごとに `?` を送って、200 ms のうちに戻ったものか `no reply` を出します。
オシロで見ると、DE は最初のスタートビットの前に上がり、最後のストップビットのすぐ後に下がります。

`RS485 mode refused` は `setMode()` が false を返したことを表します（RTS の端子を名指していない）。

## API と処理の流れ

`Serial1.setPins(-1, -1, -1, DE_PIN)` で RTS の端子を名指し、`setMode(UART_MODE_RS485_HALF_DUPLEX)` がそれを DE に
します（ESP32 と同じ）。DE を自分で動かす USART は CH32 に無いので、コアが `write()` でバイトを渡す前に上げ、送信完了の
割り込みで下げます。スケッチが何もしなくてもフレーム全体を覆います。`end()` の後も DE は Low のままです。

## 改造するとき

`DE_PIN`、速さ、問い合わせを変えられます。`setMode(UART_MODE_UART)` で普通の UART に戻り、DE の端子を手放します。
RS485 のモードではハードウェアのフロー制御は使えません。
