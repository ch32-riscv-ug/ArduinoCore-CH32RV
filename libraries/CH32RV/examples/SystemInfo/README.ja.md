# SystemInfo

[English](README.md)

ビルド対象の系列、CPU周波数、リセット理由、スケッチとヒープの情報を表示します。UART接続だけで試せます。

## 操作とAPI

端末を開いた状態でリセットすると情報を表示します。`i`を送ると空きヒープをもう一度表示します。メモリ不足を起こすための確保は行いません。

- `getChipModel()`はバイナリをビルドした系列を返します。製品ボードやパッケージの自動判別ではありません。
- `getSketchSize()`・`getFreeSketchSpace()`はリンクしたプログラムと選択したFlash領域の情報です。空き領域が設定保存用に確保されるわけではありません。
- `getHeapSize()`・`getFreeHeap()`の単位はbyteです。空き領域の分断により、合計と同じ大きさを一度に確保できない場合があります。
- `CH32RV_ESIG_FLACAP_ADDR`がある場合だけ`getFlashChipSize()`・`getUniqueId()`を呼びます。ない場合は利用できない旨を表示します。UIDは上位・下位の順で、ゼロ埋めなしの16進数として表示します。MACアドレスや秘密情報としては扱いません。

チップのFlash容量とリンク対象の容量が違う場合はPart Numberを確認します。値はそのビルド・チップの情報なので、別の基板の仕様値として扱わないでください。

## 実行前の準備

ボードと正確なPart Numberを選び、スケッチの端子を回路図と照合します。ログはハードウェア`Serial`の115200 baud・8N1です。アダプタRXをボードTX、アダプタTXをボードRXへ接続し、GNDを共通にします。I/O電圧を合わせてください。基板のUSB端子だけでこのUARTが見えるとは限りません。

生成された`sketch.yaml`にビルドprofileがあります。ビルド成功は配線や実機動作の確認とは別です。[ビルド規則](../../../../docs/examples-build-rules.ja.md)と[書き込み経路](../../../../docs/upload-routes.ja.md)も参照してください。
