# CH32RVLogicCapture

[English](README.md)

GPIO のポート 1 つ(16 本の入力)を、DMA でまとめて RAM に取り込むライブラリです。ロジックアナライザの入口に使えます。
全系列で使えます。実機で確かめたのは CH32H415 / H416 / H417 だけで、ほかの系列はビルドだけ確かめています。

| 系列 | タイマー | DMA |
|---|---|---|
| CH32H415〜H417 | TIM6 | DMA2 チャネル 8(DMAMUX の要求 122) |
| CH32V303 / V305 / V307 / V317、V407 / V467 | TIM6 | DMA2 チャネル 3 |
| CH32V103、V203 / V208、V205、L103 / M103、X305 / X315 | TIM4 | DMA1 チャネル 7 |
| CH32V002〜V007、M007、V003、X033 / X035 | TIM2 | DMA1 チャネル 2 |
| CH32M030 | TIM3 | DMA1 チャネル 3 |

- 24 本のポート(X033 / X035、X305 / X315)は、下の 16 本だけを取り込みます。
- TIM2 で PWM や `tone()` も動かす小さな系列では、それらが TIM2 を使っている間は `begin()` が失敗します。
- 速さの上限(`maxContinuousRate()` = F_CPU / 11)は H417 で測った値です。ほかの系列では測っていません。

```cpp
#include <CH32RVLogicCapture.h>

CH32RVLogicCapture logic;
static uint16_t buf[32768];
logic.begin(PORT_E, 10000000);              // ポートと、1 秒あたりのサンプル数
logic.startContinuous(buf, 32768);          // 16384 ずつの半分を交互に埋める
if (const uint16_t *half = logic.readBuffer()) { ... }   // loop() から

uint32_t rate = logic.captureBurst(buf, 32768);   // 1 回だけ、速く
```

各サンプルは、そのポートの入力レジスタの値です(bit n が Pxn)。端子のモードに関係なく読めます。

## 2 つの方式(CH32H417、HCLK 100 MHz での実測、2026-10-21)

| | 連続(`startContinuous()`) | 1 回取り(`captureBurst()`) |
|---|---|---|
| 仕組み | TIM6 の更新で DMA2 のチャネル 8 が読む | タイマーなしで DMA が続けて読む |
| 速さ | F_CPU ÷ 11 = 9.09 MS/s まで | 1 サンプル 5 クロック = 20 MS/s |
| 時間の正確さ | タイマーで決まり、正確 | DMA の速さで決まる。バスの取り合いで揺れる |
| 長さ | 循環バッファで、いつまでも | 65535 サンプルまで |

**連続の方式**
- ポートからの DMA の転送は 1 回に HCLK の 8 クロックかかり、その最中に来た要求は捨てられます。そのため 1 本では
  12.5 MS/s（F_CPU ÷ 8）が上限です。
- USB で同時に流していると、バッファが USB の転送と同じ 128 KB の SRAM のバンクにあるとき、それより遅くても抜けます
  （バッファを 1 つのバンクに置いた 9.09 MS/s で 151 ppm）。`begin()` は当面 F_CPU ÷ 11 で止めます。バッファの置き方と、
  2 本の DMA で 20 MS/s を出す形を検討中です（測った結果は docs/h417-capture.ja.md）。

**1 回取りの方式**
- 間隔はタイマーではなく DMA の速さで決まります。CPU や別の DMA が同時にバスを使うと、サンプルが 1 クロック遅れることがあります。
  16 ビットで約 320 周期を取ったうち、6 か所が数サンプルずれました。
- 実行中は割り込みを止めます。

## そのほか

- タイマーは、コアのタイマー管理(`CH32RVTimer.h`)を通して借ります。`analogWrite()` / `tone()` / Servo と取り合いません。
- 連続の方式で `readBuffer()` が返した半分は、次の `readBuffer()` まで使えます。DMA がそこへ戻ってくるまでに処理を済ませてください。
  時間は「半分のサンプル数 ÷ 速さ」です。スケッチが受け取る前に次の回が来た半分は `overruns()` に数え、そのデータは失われます。
- バッファは、DMA が届く RAM(グローバル変数や static)に置いてください。
- USB の SuperSpeed で流す例は `LogicStream` です(H417)。9.09 MS/s × 2 バイト = 18 MB/s で送ります。
- 入力の電圧は、そのポートの電源の電圧までです。PE7〜PE15 などは VIO18 の端子です(CH32RVHsAdc の README の
  「入力の範囲」を参照)。
