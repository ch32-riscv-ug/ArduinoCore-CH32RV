# PiocDmx

[English](README.md)

PIOC で DMX512 のコントローラーを作ります。`dmx_tx.S` が 32 チャネルのユニバースを IO0 に送ります（ブレーク、その後の
マーク、スタートコード 0、チャネルを 250 kbit/s・8N2 で）。1 秒に 40 回。その間メインのコアは次の値を計算します
（チャネルを順に流れるゆっくりした明滅）。

## 必要なものと配線

PIOC のある石（X035 / X033、V205、H41x）と RS-485 のドライバー（MAX485 など。送信だけなら DE と RE を High に）。
IO0 の端子（スケッチの `IO0_PIN`: CH32H417 は PA0、CH32X035 は PC7、CH32X033 は PC18（SWD と兼用）、CH32V205 は PB10）を
ドライバーの DI へ。A / B を DMX の線（XLR の 3 番 / 2 番）へ、GND は共通、線の遠い端に 120 Ω の終端。

## 操作と期待する結果

アドレス 1 に設定した DMX の機器や調光器がチャネル 1 に、以下 32 まで従います。各チャネルの明るさが約 4 秒で上下し、
順にずれていきます。

## API と流れ

- バイトは共有レジスタ d8〜d31 で 24 個ずつ渡します。d0 がその数、d1 / d2 がビットの待ち（4 us を
  `CH32RVPioc::clockHz()` から計算）、d5 のビット 0 でバイトの前にブレーク（23 ビット Low: 92 us）とその後のマーク
  （3 ビット: 12 us）を出します。最初の塊はスタートコードでパケットを始め、残りはそれに続けます（スロットの間は最大
  1 秒まで空けてよい）。
- `command()` で送り始め、`waitDone()` で最後のストップビットまで待ちます。PIOC は `begin()` で一度起こしたまま
  動かし続けるので、パケットの間も線は High（マーク）のままです。
- ユニバースは最大 512 チャネルです。`CHANNELS` と 25 ms の休みで更新の速さが決まります（512 チャネルは 250 kbit/s で
  約 23 ms）。

H417・X035・V205 で、WireSkein の `dmx512` が送ったとおりのパケット（スタートコード 0 と 30 スロットを 3 つ）を読むことを
確かめました（2026-11-23、pioc::test_pioc_dmx）。
