# PiocIrNecRx

[English](README.md)

PIOC で NEC 方式の赤外線リモコンのフレームを受けます。`nec_rx.S` が、赤外線の受光モジュール（38 kHz。TSOP38238 や VS1838B
など）が IO0 に出す信号を、コマンド 1 つで 1 フレームずつ 32 ビットに読み解きます。その間メインのコアは別の仕事を続けられます。
受けたアドレスとコマンドを Serial に出します。

## 必要なものと配線

PIOC のある石（X035 / X033、V205、H41x）と、38 kHz の赤外線の受光モジュール。モジュールの出力を IO0 の端子（スケッチの
`IO0_PIN`。CH32H417 は PA0、CH32X035 は PC7、CH32X033 は PC18（SWD と兼用）、CH32V205 は PB10）に、電源は石と同じ 3.3 V、GND は共通に。モジュールの出力は
搬送波がある間 Low、ない間 High です（多くのモジュールは出力にプルアップを持っています）。

## 操作と期待する結果

Serial を 115200 bps で開き、NEC 方式のリモコンのボタンを押すと、`address 0x00 command 0x45` のように出ます。拡張アドレス
（2 バイト目がアドレスの反転でない）は `(extended)` 付きの 16 ビットで、押し続けると `repeat` が続きます。

## API と処理の流れ

- 時間は「刻み」で数えます。1 刻みは PIOC の約 773 × d1 サイクル（d1 はスケッチが `CH32RVPioc::clockHz()` から約 75 µs に
  なるように決めます）。線は 1 刻みに 1 回見るので、時間は ±1 刻みで分かります。
- しきい値は NEC の時間の中ほどです: ビットの空白 1125 µs より長ければ 1、リーダーの空白 3375 µs より長ければフレーム（短ければ
  繰り返しの符号）、リーダーの点灯は 6 ms 以上。それぞれ「256 − 刻み数」で d2〜d4 に渡します。
- `command()` で 1 フレームを待ち始め、`waitDone()` の答えが 0 ならフレーム（d8〜d11 に 32 ビット、最初のビットが d8 の bit 0）、
  1 なら繰り返しの符号、2 なら途中で切れた（同じ線の高さが 256 刻み続いた）です。
- 何も来なければ PIOC は待ち続けるので、`waitDone()` が時間切れになったら `begin()` し直して止めます。
- 6 ms より短い Low は雑音として読み飛ばし、次のリーダーを待ちます。

H417（PIOC 100 MHz）・X035（48 MHz）・V205（160 MHz）で、プローブの spi-controller が MOSI に受光モジュールの出力の形（1 ビットが
562.5 µs の 1 単位）を出し、通常のアドレス（0x00 / 0x45）・拡張アドレス（0x1234 / 0x5A）・繰り返しの符号を正しく受けています
（2026-11-20、pioc::test_pioc_nec_rx）。実際の受光モジュールとリモコンではまだ試していません。
