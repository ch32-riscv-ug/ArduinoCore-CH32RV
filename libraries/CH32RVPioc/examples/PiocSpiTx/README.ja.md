# PiocSpiTx

[English](README.md)

PIOC で SPI の送信（モード 0、MSB から）をもう 1 つ増やします。`spi_tx.S` が IO0 に SCK、IO1 に MOSI を出し、その間メインの
コアは別の仕事を続けられます。CS はスケッチが出す普通の端子です。100 ms ごとに 16 ビットのカウンタを 1 MHz で送ります
（たとえば 74HC595 を 2 つつないだものへ）。

## 必要なものと配線

PIOC のある石（X035 / X033、V205、H41x）。

| 石 | SCK（IO0） | MOSI（IO1） | CS |
|---|---|---|---|
| CH32H417 | PA0 | PC0 | PA1 |
| CH32X035 | PC7 | PC19 | PA1 |
| CH32V205 | PB10 | PB11 | PB2 |

受け手（シフトレジスタ、LED のドライバ、表示器など）の SCK・データ・CS（74HC595 ならラッチ）につなぎ、GND も共通に。
受け手が無くても、ロジックアナライザで見られます。

## 操作と期待する結果

書き込むと、100 ms ごとに CS が Low になり、2 バイト（カウンタの上位、下位）が 1 MHz で出ます。74HC595 なら、出力が数えて
いくのが見えます。

## API と処理の流れ

- 送るバイトは共有レジスタの d8〜d31 で、24 バイトずつ渡します。d0 がそのバイト数、d1 が半周期の待ちの回数です。
  半周期は PIOC の 3 × d1 + 6 サイクルで、`CH32RVPioc::clockHz()` と速さから計算します（1〜256 回）。
- 各ビットは、SCK が Low の間に MOSI を出し、半周期待って SCK を High に（受け手が読む）、半周期待って Low に戻します。
- `command()` で送り始め、`waitDone()` で最後のビットまで待ちます。24 バイトを超える分は、CS を Low のまま続けて渡します。
- PIOC は一度 `begin()` したら走らせたままにします（SCK を Low に保つため。`loadSram()` の間は端子が浮きます）。
- SCK の速さは PIOC のクロックの 1 / 18（1 回）から 1 / 1548（256 回）まで。48 MHz（X035）で約 2.7 MHz〜31 kHz、
  100 MHz（H417）で約 5.6 MHz〜65 kHz、160 MHz（V205）で約 8.9 MHz〜103 kHz です。下限より遅くは、スケッチが 256 回に切り詰めます。
- 受け取り（MISO）はありません。PIOC の端子は 2 本だけです。

H417（PIOC 100 MHz）と V205（160 MHz）で、100 kHz と 1 MHz の送信を WireSkein の `spi` で判定して通っています（2026-11-20、
pioc::test_pioc_spi_tx。CS の中のバイト列、モード 0、MSB から。測った SCK は 952 kHz・99.5 kHz と 1.00 MHz・103.6 kHz で、
上の式との差は 3 % 以内。V205 の 100 kHz は下限の 103 kHz になる）。X035 は台に IO1（PC19）の線が無く、まだです。
