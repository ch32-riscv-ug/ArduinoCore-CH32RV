# CH32RVUhsif

[English](README.md)

CH32H415 / H416 / H417 の UHSIF（高速の並列インターフェース）を使うライブラリです。UHSIF は、クロックごとに動く状態機械で 8 / 16 / 32 ビットのデータ線を扱い、socket の DMA で RAM に書きます。WCH はレジスタを公開しておらず、バイナリのライブラリ（`libUHSIF.a`）だけを配っています。このライブラリはそれを使わず、実機で測った結果から作りました（調べた記録は [docs/h417-uhsif.ja.md](../../docs/h417-uhsif.ja.md)）。

ロジックアナライザとして取り込むだけなら、この上に作った [CH32RVLogicCapture](../CH32RVLogicCapture/README.ja.md) の `begin(UHSIF_DATA, rate)` が簡単です。

## できること（CH32H417 で確かめたこと、2026-11-11）

- データ線の取り込み。クロックは内部の SYSCLK（400 MHz）か USBHS の PLL（480 MHz、水晶から）を ÷ 1〜64 したもの。
- 状態機械。状態は 255 個までで、出口は左右の 2 つです。右へ進む条件（真理値表）は 16 通りまで書けます。
- データのカウンター。
- スレッド 4 つ。どれも、バッファーの輪に CPU 抜きで書き続けます。
- 状態機械からの割り込み。
- データ線の幅 8 / 16 / 32 ビット（2026-11-14、100・200・400 MS/s で 1 バッファーずつ確かめた）。
- データの比較器（決まった値に一致、または変化した）と、制御線の比較器（2026-11-14）。パターンやエッジのトリガー、変化したときだけ積む取り込みに使えます。

まだ扱わないもの: バスへの出力、外部のクロック、制御線の出力、24 ビット幅。ブロックに無いもの（直列の入出力、CRC、端子とビットの自由な対応）は [docs/h417-uhsif.ja.md](../../docs/h417-uhsif.ja.md) の「FX3 由来の機能」にあります。

## 端子

| データ線 | 端子 | 幅 |
|---|---|---|
| DATA0〜5 | PD10〜PD15 | 8 / 16 / 32 |
| DATA6〜7 | PF0、PF1 | 8 / 16 / 32 |
| DATA8 | PF2 | 16 / 32 |
| DATA9〜12 | PC6〜PC9 | 16 / 32 |
| DATA13〜15 | PA13〜PA15 | 16 / 32 |
| DATA16〜18 | PC10〜PC12 | 32 |
| DATA19〜26 | PD0〜PD7 | 32 |
| DATA27〜29 | PF3〜PF5 | 32 |
| DATA30〜31 | PE0、PE1 | 32 |

データ線は、いつも DATA0 から、この順です（UHSIF の PORT16 から）。ほかの端子を選んだり、順番を入れ替えたりはできません（測った結果）。

| 制御線 | 端子 |
|---|---|
| CTRL0〜4 | PB14〜PB10 |
| CTRL5〜12 | PE15〜PE8 |
| CTRL13 | PE7 |
| CTRL14、15 | PF13、PF12 |

制御線は状態機械の入力（`Ctrl0` + n）と、制御線の比較器で使えます（AFIO の UHSIF_PORT_RM が 0 のとき）。データ線と同じく、端子は決まっています。

端子のモードに関係なく読めます（入力、別の機能、GPIO の出力のどれでも）。`begin()` は端子に触りません。入力の電圧は、その端子の電源の電圧までです。

## 使い方

```cpp
#include <CH32RVUhsif.h>

CH32RVUhsif uhsif;
static uint16_t ring[8192] __attribute__((aligned(32)));

uhsif.begin(63);                                  // SYSCLK / 64（USBHS の PLL なら begin(2, CH32RVUhsifClock::UsbhsPll)）
uhsif.setStates(states, 2, start);                // 状態機械
uhsif.setDataCounter(2048 - 2);                   // バッファー 1 つ分で上限
uhsif.setRing(0, ring, 4096, 4, 4096);            // スレッド 0: 4096 バイト × 4
uhsif.onInterrupt([] { /* 状態機械の Interrupt */ });
uhsif.start();
```

全体は例の [UhsifStates](examples/UhsifStates/README.ja.md) にあります。

### 幅

`setBusWidth(8 / 16 / 32)` を `begin()` のあと、`start()` の前に呼びます（`begin()` は 16）。1 サンプルは 1 / 2 / 4 バイトで、8 ビットでは 1 語に 4 サンプル（DATA0 が下位のバイト）です。データのカウンターは幅に関係なくサンプルを数えます。必要な帯域は幅に比例します（200 MS/s で 200 / 400 / 800 MB/s）。

### 比較器（トリガー）

| 関数 | 状態機械の入力 | 真になるとき |
|---|---|---|
| `setDataMatch(value, mask)` | `DataMatch` | `mask` のデータ線が `value` と同じ |
| `setDataChange(watch)` | `DataMatch` | `watch` のデータ線のどれかが、1 クロック前から変わった |
| `setControlMatch(value, mask)` | `ControlMatch` | `mask` の制御線が `value` と同じ |

- 比較器は、ラッチした値ではなく端子の今の値を見ます。
- 「一致しない」を待ってから「一致する」を待つと、エッジのトリガーになります。一致だけを待つと、始めたときに一致していれば、すぐ進みます。例の [UhsifTrigger](examples/UhsifTrigger/README.ja.md) がエッジのトリガーです。
- 待つ段も、2 つの状態を行き来させます（同じ状態へ戻る遷移は判断し直しません）。
- `setDataChange()` で、変化したときだけ `Push` すると、変化した値だけが並びます。変化した時刻は残りません。浮いた端子のノイズも変化として拾うので、`watch` は使う線だけにします。

### 状態と遷移

- 各クロックで、状態は `goRight` が真なら右の遷移で、偽なら左の遷移で出ます。
- `goRight` は、状態の 4 つの入力 a〜d の真理値表です（bit (a + 2b + 4c + 8d)）。0 なら、いつも左です。
- 遷移には、入る先の状態と、そのときの出力（alpha と beta）を書きます。
- `start()` は、`start` の遷移で最初の状態に入ります。

| 出力 | 意味 |
|---|---|
| `SampleData`（alpha） | データ線をラッチする |
| `Push` | ラッチした値を、そのスレッドの socket に渡す |
| `CountData` / `ResetDataCount` | データのカウンターを +1 / 0 にする |
| `Interrupt` | `onInterrupt()` のコールバックを呼ぶ |
| `thread(n)` | どのスレッドに渡すか（0〜3） |

| 入力 | 意味 |
|---|---|
| `Ctrl0` + n | 制御線 CTRLn（端子は上の表） |
| `DataCountHit` | データのカウンターが上限にいる |
| `ControlMatch` | 制御線の比較器（`setControlMatch()`） |
| `DataMatch` | データの比較器（`setDataMatch()` / `setDataChange()`） |
| `DmaReady` | 今のスレッドの socket が受け取れる |
| `One` | いつも 1 |

ハードウェアの決まり（測った結果）:

- 同じ状態へ戻る遷移では、alpha はもう出ません。毎クロック取り込むには、2 つの状態を行き来させます。
- `ResetDataCount` は、その遷移で入った状態の判断にはまだ効きません。リセットで入る状態は、カウンターを見ずに左へ出るようにします。
- データのカウンターの上限は「1 つのバッファーのサンプル数 − 2」にします（8192 サンプルなら 8190）。

### バッファーの輪

- `setRing(n, first, bytes, count, stride)` で、スレッド n は `count` 個のバッファー（k 番目は `first + k × stride`）を順に書き、輪になって続けます。
- `bytes` は 64 の倍数で、65472 まで。バッファーは DMA の届く RAM（グローバルや static の配列）に、32 バイト境界で置きます。32 の倍数でない大きさでは CPU が止まりました（DMA がバッファーの外に書いたとみています）。
- socket はバッファーを 1 つ書くごとに止まり、ライブラリが割り込みで次の descriptor へ進めます。止まっている間に来たサンプルは捨てられるので、スレッドがその socket に戻るのは、割り込みが済んでからにします。
- 抜けを無くすには、2 つのスレッドを交互に使います。片方が止まって再開を待つ間、もう片方が書きます。CH32RVLogicCapture の UHSIF の取り込みがこの形です。1 つのバッファーは 20 µs 以上の長さにします。
- 1 回だけ取って止めるとき（積むのをやめるとき）は、最後の 64 バイトに満たない端数がブロックに残り、書き出されません（DMA は 64 バイトの burst で書く）。欲しい分より 64 バイト多く積みます（例の UhsifTrigger）。
- バッファーが 1 つだけの輪で取り続けると、同じバッファーへ書き直し続けるので、止めた時点の中身は新しい分と古い分の継ぎはぎになります。
- 止めずに輪を回し続ける形（転送の大きさ 0）も動きますが、socket はどのバッファーも最後の 16 バイトを書かずに次へ進み、その 8 サンプルは失われました。使っていません。

### 止める

`stop()` は UHSIF をリセットして止めます。設定（`begin()`、`setStates()`、`setDataCounter()`、`setRing()`）も消えるので、もう一度 `start()` する前に設定し直してください。バッファーの中身は残ります。

## エラー

操作は `bool` を返し、理由は `lastError()` と `lastErrorName()` で読めます。

| `CH32RVUhsifError` | 意味 |
|---|---|
| `NotBegun` | `begin()` の前 |
| `ClockFailed` | USBHS の PLL が立ち上がらない（水晶が無い？） |
| `InvalidArgument` | 番号、大きさ（64 の倍数）、位置（32 バイト境界）のどれかが違う |
| `TooManyFunctions` | `goRight` の真理値表が 16 通りを超えた |
| `Running` | 動いている間は設定を変えられない（先に `stop()`） |

## そのほか

- UHSIF は 1 つなので、同時に `begin()` できるのは 1 つのオブジェクトだけです。
- SRAM へは、2 スレッドで 400 MHz（800 MB/s）まで流れました。ただ 400 MHz では、390 kHz の PWM の 1 周期が 1 か所で 2 つに割れました（端の近くを取ったときの乱れとみています）。200 MHz 以下では割れませんでした。
- RM の UHSIF の仕様は 125 MHz までです。速い信号での確かさ（セットアップとホールド、16 本のずれ）は、まだ外の信号源で見ていません。
- 1 つのバッファーごとに割り込みを出すときは、割り込みの間隔を 20 µs 以上にしてください。200 MHz で 256 サンプルごとにしたら、CPU が割り込みの処理だけになりました。
