# UhsifStates

[English](README.md)

UHSIF の状態機械を書いて、16 本のデータ線を毎クロック（6.25 MHz）取り込み、4 つのバッファーの輪に書きます。バッファーが 1 つ埋まるたびに状態機械が割り込みを出すので、その数を数えます。CH32H415 / H416 / H417 用です。

## 必要なものと配線

対象のボードと UART のモニターを用意します。配線は要りません。データ線（PD10〜PD15、PF0〜PF2、PC6〜PC9、PA13〜PA15）に信号をつなぐと、その値が表示に出ます。

## 操作と期待する結果

1 秒ごとに、埋まったバッファーの数、書かれたバイト数、最新のサンプルが出ます。SYSCLK が 400 MHz なら、`3051 buffers/s, 12468224 bytes/s` 前後です（6.25 MHz × 2 バイト = 12.5 MB/s、2048 サンプル × 3051 ≒ 625 万）。最新のサンプルの bit n は DATAn の値です。

`begin: ...` や `setup: ...` が出たら、`lastErrorName()` の名前が理由です（README の「エラー」）。

## API と処理の流れ

1. `begin(63)` でクロックを SYSCLK ÷ 64 にします。
2. `setStates()` で 2 つの状態を書きます。どの遷移も `SampleData`（ラッチ）と `Push`（積む）を出すので、毎クロック 1 サンプル取れます。状態 1 は、データのカウンターが上限（2048 − 2）に来たら右へ出て、カウンターを戻し、割り込みを出します。
3. `setRing(0, ring, 4096, 4, 4096)` で、スレッド 0 が 4096 バイトのバッファー 4 つを順に書きます。
4. `start()` で動かします。

## 改造するときの注意

- 1 スレッドなので、バッファーを替えるたびに、次の descriptor を読む間（約 150 ns）のサンプルが抜けます。6.25 MHz ではほぼ 1 サンプル以内です。速いクロックで抜けを無くすには、2 スレッドを交互に使います（CH32RVLogicCapture の `begin(UHSIF_DATA, rate)`）。
- データのカウンターの上限は、バッファーのサンプル数 − 2 にします。
- クロックを上げるときは、割り込みの間隔を 20 µs 以上に保ちます。
