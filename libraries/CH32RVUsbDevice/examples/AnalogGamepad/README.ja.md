# AnalogGamepad

[English](README.md)

2軸のアナログジョイスティック、または2つの可変抵抗とボタンをUSBゲームパッドとして使います。[AnalogInputToPwm](../../../CH32RV/examples/AnalogInputToPwm/README.ja.md)と[ButtonDebounce](../../../CH32RV/examples/ButtonDebounce/README.ja.md)で扱う数値変換と安定した入力状態を組み合わせます。

## 配線と校正

各可変抵抗の両端をADCに適合する電源とGNDへ、摺動端子を`X_PIN`（`A0`）・`Y_PIN`（`A1`）へつなぎます。ジョイスティックモジュールは、基板の入力許容範囲内のアナログ出力を持つものを使います。通常は開いているボタンを`BUTTON_PIN`（`PB0`）とGNDの間へつなぎます。GNDを共通にし、別名を実padへ読み替えてUART・USB・debugとの競合を避けます。USBの5 Vで給電したモジュールの出力が、ADCへそのまま接続できるとは限りません。

電源投入・リセット前に両軸を中央へ戻します。setup()では12 bitの読み取りを選び、軸ごとに32回の平均で中央値を得ます。Flashへの校正保存は行いません。電源端に近い値ならUARTへ表示して開始を中止するので、配線と中央位置を直してリセットします。普通の可変抵抗2つなら手で中央付近へ合わせます。機械的な中央をスケッチが自動判別するわけではありません。

OSのゲームコントローラ確認画面を開きます。静止時はX/Yが中立、各軸を両端へ動かすと生report換算で約−127～+127になります。ホストの画面は別の尺度で表示する場合があります。最初に一度解放してからボタンを押す・離すと、ボタン1が変化します。ほかの軸は0、hatは中立のままです。

## 換算と送信

中央値の両側64 ADC countを中立帯にします。`axisValue()`は残りの正負の領域を別々に換算し、32 bitで計算して、生値を選択したADC範囲へ制限します。中央値の事前検査で換算式の分母が0になることを避けます。中立帯は中央付近の揺れを抑えるもので、軸全域の雑音を除くものではありません。方向を反転したい場合は、換算した値の符号を反転してreportへ入れます。

`CH32RVUsbDeviceGamepadReport`は現在の全状態です。`buttons = 1UL`でボタン1、0で解放を表します。10 msごとに全reportを送り、未使用のfieldは中立の既定値にします。`sendReport(report, 0)`が失敗したら次の周期で入力を読み直して再試行し、古い軸位置を蓄積しません。ボタンのチャタリング除去は送信間隔とは別の25 msです。再接続時には解放までボタンを無効にしますが、軸は校正済みの現在位置を反映します。

中央がずれる・軸の可動範囲が非対称といった場合は、中立帯の調整や明示的な最小・最大値の校正を追加します。起動時の平均化は、精密な電圧測定やジョイスティックの完全な校正手順ではありません。

## USBの状態とreport API

deviceとHID機能は`setup()`より前に宣言します。`device.begin(config)`は内部の開始であり、ホストの認識完了ではありません。`device.mounted()`でホストによる設定済みかを確認します。MCUのUSBデータ端子につながるコネクタとデータ対応ケーブルを使います。HIDはシリアルポートではありません。controller・clock・配線の条件は[USB Device案内](../README.ja.md)と[USB対応表](../../../../docs/usb.ja.md#対応状況)を参照してください。

`deliverEvents()`によって、登録した`onBusEvent()`の通知をloop()内で実行します。リセット・再認識ではボタン入力を無効にし、安定した解放を確認してから、新しい押下をホストへ渡します。このため、押したまま抜き差ししても即座に押下しません。ホストのsleepから起こすremote wakeは実装しません。

`sendReport(report, 0)`はendpointの空きを待たず、現在の全状態を送ろうとします。成功はUSB転送用に受け付けた意味であり、ホストアプリが操作したことの保証ではありません。次のloop()でも入力を読み続けられます。送信できない間に完結した短い押下はまとめられる場合があります。全操作を積むキューではなく、最新状態を扱う例です。

## ボードとUARTの準備

ボードと正確なPart Numberを選び、各端子を回路図と照合します。Genericの別名はvariantの定義であり、基板コネクタの表示と同じとは限りません。UART・書き込み／debug・ほかの周辺回路との端子競合を避けます。生成された`sketch.yaml`のprofileはビルド条件であり、配線の確認結果ではありません。

ログはハードウェア`Serial`の115200 baud・8N1です。アダプタRX←ボードTX、アダプタTX→ボードRX、共通GNDで接続し、I/O電圧を合わせます。このUARTはUSB HIDとは別で、基板のUSB端子から自動的に見えるわけではありません。
