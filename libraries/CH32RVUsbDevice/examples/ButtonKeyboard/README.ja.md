# ButtonKeyboard

[English](README.md)

物理スイッチでキーボードの1キーを押下・解放します。入力の処理は[ButtonDebounce](../../../CH32RV/examples/ButtonDebounce/README.ja.md)から読むと追いやすくなります。

## 配線と操作

通常は開いている押しボタンを`BUTTON_PIN`（`PA1`）とGNDの間につなぎます。内部pull-upにより、離すとHigh、押すとLowです。UARTや基板のUSB・debug配線と競合する場合は、別の有効なGPIOへ変更します。

試し書き用のテキストエディタを開き、その文書へフォーカスを合わせます。接続後に一度スイッチを離し、押す・保持する・離すを試します。押している間はAのキー位置を送り、ホストの設定によって文字が繰り返されます。解放すると保持が終わります。入力される文字はホストの配列、Caps Lock、ほかの入力機器のShift等でも変わります。

`KEY_USAGE`は`CH32RV_USB_HID_KEY_A`（usage `0x04`）を使い、ASCIIではありません。生のusageはキー位置であり、言語によらず同じ文字を入力する指定ではありません。

## 状態の扱い

25 msのチャタリング除去を行い、押下も解放も全状態のreportとして送ります。空の`CH32RVUsbDeviceBootKeyboardReport`は保持キーなしを表します。状態が変わった場合や接続の初期化時に、10 ms以上空けて送信を試します。送信済み状態を更新するのは`sendReport()`成功後だけです。解放の送信に失敗しても送信済みにはせず、現在の解放状態で再試行します。エラー表示の頻度も制限します。

短い押下、長押し、押したままの再接続を試します。再接続時は中立を送り、安定した解放の後から新しい押下を受け付けます。ケーブルが抜けている間は解放を送れないため、その間の取り外し処理はホスト側が担います。

## USBの状態とreport API

deviceとHID機能は`setup()`より前に宣言します。`device.begin(config)`は内部の開始であり、ホストの認識完了ではありません。`device.mounted()`でホストによる設定済みかを確認します。MCUのUSBデータ端子につながるコネクタとデータ対応ケーブルを使います。HIDはシリアルポートではありません。controller・clock・配線の条件は[USB Device案内](../README.ja.md)と[USB対応表](../../../../docs/usb.ja.md#対応状況)を参照してください。

`deliverEvents()`によって、登録した`onBusEvent()`の通知をloop()内で実行します。リセット・再認識ではボタン入力を無効にし、安定した解放を確認してから、新しい押下をホストへ渡します。このため、押したまま抜き差ししても即座に押下しません。ホストのsleepから起こすremote wakeは実装しません。

`sendReport(report, 0)`はendpointの空きを待たず、現在の全状態を送ろうとします。成功はUSB転送用に受け付けた意味であり、ホストアプリが操作したことの保証ではありません。次のloop()でも入力を読み続けられます。送信できない間に完結した短い押下はまとめられる場合があります。全操作を積むキューではなく、最新状態を扱う例です。

## ボードとUARTの準備

ボードと正確なPart Numberを選び、各端子を回路図と照合します。Genericの別名はvariantの定義であり、基板コネクタの表示と同じとは限りません。UART・書き込み／debug・ほかの周辺回路との端子競合を避けます。生成された`sketch.yaml`のprofileはビルド条件であり、配線の確認結果ではありません。

ログはハードウェア`Serial`の115200 baud・8N1です。アダプタRX←ボードTX、アダプタTX→ボードRX、共通GNDで接続し、I/O電圧を合わせます。このUARTはUSB HIDとは別で、基板のUSB端子から自動的に見えるわけではありません。
