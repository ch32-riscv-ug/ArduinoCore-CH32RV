# Gamepad

English: [README.md](README.md)

6軸、ハット、ボタン bitmap を持つ HID ゲームパッドのテスト入力を送ります。

## 必要なものと配線

PC のゲームコントローラ状態表示アプリと UART モニタ。外付けジョイスティックは不要です。

## 操作と期待する結果

1. 約500 ms ごとに軸値とハット、ボタンが変わります。
2. UART の `GAMEPAD_TX` と PC の状態を照合します。
3. ボタンは先頭8個が順に有効になり、軸は約 -127～127 のテスト値を循環します。

## 設定と制約

report は32ボタンを表せますが、この例が循環するのは8個です。アナログ入力へ変更する場合は、ADC の分解能と中心値を軸の範囲へ変換します。

## API の使い方と改造のポイント

| API | この例での使い方 |
|---|---|
| `send(x, y, z, rz, rx, ry, hat, buttons)` | 六つの軸、ハット、ボタンの全状態をまとめて送ります。軸の引数順に注意します。 |
| ハットの定数 | 中立・上下左右・斜めを指定します。角度の度数を直接渡す形式ではありません。 |
| `buttons` | bitmap です。`1UL << 0` が先頭ボタン、複数なら bit を OR で合わせます。 |
| `sendReport(report)` | report 構造体に状態をまとめてから送る場合に使います。 |

実ジョイスティックは `analogRead()` の分解能に応じて、中心が0になるよう軸値へ変換します。
中心の揺れには dead zone を設け、範囲を制限してから `int8_t` に変換してください。

report は変化分ではなく全状態です。ボタンを離すときはその bit を0にし、ハットを離したら中立を送ります。
`send()` が `false` のときは送信間隔や列挙状態を確認し、次の回で最新の状態を送ります。
