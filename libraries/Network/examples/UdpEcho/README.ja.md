# UdpEcho

[English](README.md)

ポート 9000 の UDP サーバーです。届いたデータグラムを送り主へそのまま返し、誰からどれだけ届いたかを表示します。

## 操作

`UDP echo on 192.168.x.y:9000` とアドレスが出ます。PC から `nc -u 192.168.x.y 9000` を実行して行を打つと、そのまま返り、ボードは `#n アドレス:ポート 大きさ` を表示します。512 バイトより長いデータグラムは 512 に切って返し、ログにもそう出ます。

## API と改造時の注意

TCP と違い、UDP は送ったときの区切りのまま届きます。`parsePacket()` 1 回で 1 データグラムで、`read()` はそのうちバッファの大きさまでを返します（残りは捨てます）。届く保証はありません。データグラムも返事も失われることがあるので、UDP の上のプロトコルには再送が要ります。`beginPacket()` / `write()` / `endPacket()` で 1 データグラムを送ります。送れなかったときは、`endPacket()` が false を返します。

## 実行前の準備

Ethernet の MAC を持つボードを選び（生成された profile は CH32V307。V208、V317、V407 / V467、H415〜H417 も同じ書き方で動きます）、RJ45 を DHCP サーバーのあるネットワークにつなぎます。ログはハードウェア `Serial` の 115200 baud・8N1 です。アダプタ RX をボード TX、アダプタ TX をボード RX へ接続し、GND を共通にします。基板の USB 端子にはこの UART は出ていません。

通信の処理は `delay()` の中と各 `loop()` の後で進みます。スケッチが poll の関数を呼ぶ必要はありません。ビルドが通っても、ケーブルやネットワークの確認にはなりません。[ビルド規則](../../../../docs/examples-build-rules.ja.md)と[書き込み経路](../../../../docs/upload-routes.ja.md)も参照してください。
