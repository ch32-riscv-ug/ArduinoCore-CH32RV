# HttpsGet

[English](README.md)

HTTPS でページを取得します。サーバーの証明書を 1 つのルート証明書で確かめ、決まった TLS の版、ハンドシェイクの時間、HTTP の状態コード、本文の大きさを表示します。接続に失敗したときは、Mbed TLS のエラーと証明書の検証のフラグを表示します。

## 動かす前に

- Ethernet の MAC と乱数の回路（RNG）を持つボード: CH32V307 / V317、V407 / V467、H415〜H417。
- ボードの RJ45 を、DHCP があってインターネットへ出られる LAN につなぐ。
- シリアルモニタは `Serial`、115200 baud。
- **CH32V307 / V317:** ハンドシェイクに 30〜40 KB のヒープが要ります。出荷時の RAM 64 KB では入らないので、ツール → Flash / RAM Split → 192 KB + 128 KB を選びます。ヒープが足りないと `connect()` が失敗し、エラーは -0x7F00 か -141（メモリー不足）です。

## 操作

`Address ...` の後、SNTP を最大 10 秒待ち（証明書の日付は時計が合ってから確かめるため）、1 分ごとにページを取得します。

```text
Address 192.168.1.88
TLS 0x304 in 1830 ms
HTTP 200, 2345 bytes
```

`0x304` が TLS 1.3、`0x303` が TLS 1.2 です。時間と大きさはサーバーと系列で変わります。

## API

- `setCACert(pem)` は、サーバーを 1 つのルート証明書で確かめます。PEM はポインタで持たれるので、接続の間は残しておきます（ここでは定数の配列）。
- `connect(host, port)` はホスト名で接続します。証明書の名前と照らし合わせるので、IP アドレスでは接続しません。
- `lastError(buf, size)` は Mbed TLS のエラーの番号を返し、その文を書きます。`verifyFlags()` は検証のフラグです（鎖か名前を断ったとき 0 でない）。
- `tlsVersion()` は決まった版です。

## 変えるとき

- ほかのホスト: `HOST` と、その鎖の行き着くルートを `ROOT_CA` に入れます（`openssl s_client -connect host:443 -showcerts` で鎖が分かります）。ルートが違えば、検証のフラグが立って失敗します。確かめが働いているということです。
- ルートが複数: `setCACertBundle()` は ESP-IDF の形のバンドルを受けます（ESP32CertBundle の `x509_crt_bundle` がそのまま使えます）。
- `setInsecure()` は確かめを飛ばします。試験のときだけにしてください。途中の誰でも通信を読み、書き換えられるようになります。
