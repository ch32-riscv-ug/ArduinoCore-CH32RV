# SoftWire

English: [README.md](README.md)

任意の2 padで動くbit-bang I2C。APIは[Wire](../Wire)と同じです。

```cpp
#include <SoftWire.h>

SoftWire bus(PA1, PA2);          // SDA, SCL
```

**プルアップ抵抗は別途必要です** — 3V3へ4.7kが定番です。I2Cはオープンドレイン
なので、ソフトウェアでは代替できません。無いと線が上がらず、全アドレスが
タイムアウトします。

## なぜ要るか

ハードウェアのI2Cは、routeが名指すpadにしか出せません。CH32の小さい部品では
そのpadが使えないことがよくあります — そのpackageにbondされていない、あるいは
既に別の用途で埋まっている。CH32V003のSOP8はGPIOが全部で6本です。

I2Cはさらにbit-bangの不利が最も小さいバスです。元々オープンドレインで低速、
しかもクロックはコントローラが出すので、公称100 kHzを下回っても
プロトコル違反にはなりません — 転送が遅いだけです。

## そのまま差し替わります

`SoftWire`は`Wire`と同じ`HardwareI2C`を継承しているので、`TwoWire&`を取る
ライブラリがそのまま受け取れます。

```cpp
SoftWire bus(PA1, PA2);
Adafruit_Something device(&bus);
```

## やること

- **真のオープンドレイン。** 両padを`OUTPUT_OPENDRAIN`にします。CH32のGPIOが
  ネイティブに持っているので、HIGHは`INPUT`への切り替えではなく本当の解放です。
- **クロックストレッチに対応します。** SCLの解放は要求であって事実ではないので、
  実際に線が上がるまで待ちます。ここを間違えるのがbit-bang I2Cの典型的なバグです。
- **`endTransmission()`の戻り値はAVR互換**: 0成功 / 1データ長すぎ /
  2アドレスNACK / 3データNACK / 5タイムアウト。
- **timeout API**も`Wire`と同じ形と同じ2つの差異(既定で有効、
  タイムアウト時は必ずstop conditionで終わる)。

## やらないこと

- **クロック周波数を持ちません。** `setClock()`は半周期の**下限**を決めるもので、
  狙った周波数は出ません。ループが既に出している速度より速い値を指定しても、
  全速で回るだけです。
- **slaveモードはありません。** slaveは相手のクロックに追従する必要があり、
  ビジーループでは保証できません。`begin(address)`は他コアのコードが
  コンパイルできるよう受け取りますが、バスはコントローラのままです。

## コスト

CH32V003(flash 16 KB)で、同じスケッチをハードの`Wire`で組んだ場合と比較した実測:

| | flash | RAM |
|---|---|---|
| ハードの`Wire` | +2608 B | +152 B |
| `SoftWire` | +1904 B | +96 B |

ここでは**`SoftWire`のほうが小さい**です。ペリフェラルの状態機械・エラー復旧・
route書き込みのほうが、bit-bangより高くつくためです(SPIは逆になります —
[SoftSPI](../SoftSPI)参照)。どちらも**ヘッダを`#include`しないスケッチには
コストがかかりません**。
