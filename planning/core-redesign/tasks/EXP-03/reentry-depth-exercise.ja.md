# 処理を深く呼べば待ちが解消するか

[有限の比較模型](reentry-depth-result.ja.md)を使う教材案。人による評価前で、公開APIではない。

1. 長さ3の依存列を、継続型と入れ子深さ1／2／4で一回だけ呼ぶ。戻り値、完了集合、最大callback深さを予測する。
2. 同じ列を明示roundで進め、一回で完了することと、いずれ完了することを区別する。
3. 長さ3をcycleへ変える。深さ2のDepthLimitだけでcycleを検出したと言えるか説明する。
4. 呼出し元が保持する資源をproducerの必要資源にする。深さを4へ増やしても進まない理由を説明する。
5. producerをIRQへ変更し、許可あり／なしと外部完了刺激の前後を追う。外部完了を通常callbackへ置き換えない。
6. `.su`最大単一frameと、逆アセンブルの再帰callを照合する。callback深さ4でも失敗するcallee frameを数える理由を説明する。

予測・実行trace・修正した理解を記録する。模型の解析値を実IRQ込みのstack peakや時間保証にしない。
N07の5変更課題を実施した件数には含めない。
