# 保存中に止まる処理を数える

[X0と同期保存](save-x0-result.ja.md)の教材案。人による評価前で、公開APIではない。

1. 保存のpayloadをcaptureしてからdesiredを変え、保存される値と画面の値を予測する。
2. I2C完了済みloanを残してeraseする。媒体の復帰と、通常側でのtakeによる返却を区別する。
3. 壁時計100 msと観測ms98で、周期処理の見える期限がどう変わるかを説明する。
4. 容量1／4の仮想入力保持で損失が変わる理由を説明する。実GPIOに同じ容量があるとは推定しない。
5. 4単位でpayloadや履歴が増えずerase回数だけ増える比較から、予約量だけでは有効容量を決められないことを説明する。
6. 失敗returnでも新データがvalidな場合と、1 bankの旧データを失う場合を予測する。
7. cold-model boot後のblob公開と、PPSへ自動適用するpolicyを区別する。

予測・trace・必要だった状態を記録する。宣言時間、host結果、物理的な電断・IRQ保証を混ぜない。
