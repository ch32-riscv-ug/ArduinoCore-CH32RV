## 1. 用途から要求を出す

保存したいものを並べ、それぞれの大きさ・書く頻度・電源断で許せること・書き込み直しで残したいかを書く。要求は「どの候補が満たすか」を測る物差しにする。

| 用途 | 例 | 大きさ | 書く頻度 | 電源断で許せること | 書き込み直しで |
|---|---|---|---|---|---|
| 設定 | 動作モード、しきい値、表示の明るさ | 数 B〜数百 B | 人の操作のたび(まれ) | 旧値か新値 | 残したい |
| 校正値 | ADC のずれ、センサの係数、タッチの基準値 | 数 B〜数十 B | 工場か初回だけ | 旧値か新値。消えると困る | 残したい |
| 識別と秘密 | 機器名、ネットワークの設定(MAC、IP)、鍵 | 数十 B〜数 KB | まれ | 旧値か新値 | 残したい(鍵は消したい場合も) |
| 数え上げ | 起動回数、走行距離、使用時間 | 4〜8 B | 頻繁(秒〜分ごと) | 少し戻ってよい | 残したい |
| 記録 | センサの履歴、イベントのログ | KB〜MB | 一定間隔 | 最後の数件は失ってよい | どちらも |
| 状態の続き | 休止(スタンバイ)をまたぐ状態、最後の位置 | 数 B〜数十 B | 休止のたび | 失ってよい場合が多い | 不要 |

- この表は仮説。調査(他の環境の例、定番のライブラリ)と、このプロジェクトの用途(X0 の PD アダプタ、K0 の I2C ノブ、OEP、Network の設定)で埋め直す。
- 「状態の続き」は、フラッシュでなくてもよい(RTC の系列の BKP、V30x / L103 のスタンバイで残る RAM、`.noinit`)。フラッシュの寿命を使わない手段との分担も決める。
- 「数え上げ」と「記録」は、書き換えの寿命(10K〜300K)と、消去中に CPU が止まる系列(3〜50 ms)で、設定とは要求がまったく違う。一つの形式で全部を満たすかは、測ってから判断する。

## 2. 他の環境の調査(済み: [survey.md](survey.md)、2026-10-28)

要点(事実は survey.md の出典つき。ここでは判断に効くものだけ):

| 環境 | 形 | 確保の最小 | 電源断 | 書き込み直しで | 大きさの決め方 |
|---|---|---|---|---|---|
| ESP32 Preferences / NVS | キーと値、4 KB ページのログ(状態のビットを同じ語に書き足す) | 12 KB(Arduino の既定 20 KB) | 書いている値だけ失う | 残る(esptool は書く範囲だけ消す。全部消すメニューあり) | パーティション表 |
| ESP32 EEPROM | NVS の上の 1 つの塊 + RAM の写し | NVS と同じ | NVS と同じ | 残る | `begin(size)` |
| ESP8266 / RP2040 EEPROM | 4 KB を 1 面、RAM の写し、`commit()` で消してから書く | 4 KB | **守らない**(消した直後に切れると全部失う) | 残る(RP2040 は picotool load。ESP8266 はメニューで選ぶ) | リンカーの記号で固定 |
| STM32duino EEPROM | 最後のページ。書くたびに消して書く(バッファつき API は別) | 1 ページ | 守らない | 残る | 固定 |
| SAMD FlashStorage | スケッチのイメージの中 | — | — | **消える**(避けるべき例) | — |
| nRF52 InternalFS | LittleFS | 28 KB | 守る(ただしマウントに失敗すると黙って初期化) | 残る | 固定 |
| mbed TDBStore | 2 領域の追記ログ + 回収、RAM にキーの表 | 2 領域 | 守る | スケッチの後ろに置く例では、スケッチが伸びると動く | アプリ |
| Zephyr NVS | 追記ログ、2 セクター以上、消去後の値を 1 つの byte で比べる | 2 セクター | 守る | — | devicetree |
| Zephyr ZMS | 追記ログ。CRC と周回の数が合うものだけ有効、同じ場所は 1 周に 1 回だけ書く | 2 セクター以上 | 守る | — | devicetree |

用途の調べ(survey.md 2 章): 実際に保存されるのはほとんどが数十 B〜1 KB で、まれにしか書かない(Wi-Fi の設定 約 80 B、BNO055 の校正 26 B、grbl の設定 約 1 KB)。頻繁なのは数え上げ・最後の出力の状態・電力量で、成熟した製品は書く間隔を絞っている(ESPHome は既定で最大 1 分に 1 回、Tasmota は 1 秒ごとだが 7 個の場所を回し、変わっていなければ書かない)。AVR の EEPROM の例(10 回/秒)をそのまま 10K 回のフラッシュに移すと、約 17 分で寿命に達する。記録や証明書は、実際には SD カードやファイルシステムに置かれる。

判断に効く見立て(推測。測って確かめる):
- **書き込み直しで消さないのは、調べたどのコアでも既定**。全部消すのは、名前のついた明示的な選択(メニューかコマンド)。
- **EEPROM の大きさをメニューで選ばせるコアは無い**。ファイルシステムの大きさは、どこもメニュー。
- **Arduino の EEPROM の模倣で、電源断に耐えるものは無い**。キーと値・ファイルシステムは耐える。
- **0xE339 の系列(V20x、V30x、X315、H417)では、NVS 型(消去後 0xFF で、あとから 0 を足す)は成り立たない**。ZMS 型の規則(1 周に 1 回だけ書き、CRC と周回で見分ける)、2 つの写し + CRC なら成り立つ。littlefs も消去後のビットを 1 とみなすので、確かめが要る。
- CH32 の先例: openwch の V003 の EEPROM はオプションバイトの領域に 26 B。

### 1 章の表への反映

- 「設定」「校正値」「識別」は数十 B〜1 KB、まれに書く。ここが中心の要求。
- 「数え上げ」は、間隔を絞る前提でも、10K 回の系列では 1 ページを使い回すと足りない。複数の場所を回す(Tasmota、ZMS)か、BKP / RAM と組み合わせる必要がある。
- 「記録」「証明書」は設定の保存と分ける(ファイルシステムか SD)。

## 3. 実機で測ること

12 ファミリーのうち、ベンチにある石で測る(V003、V006、V103(今は止まっている)、V203、V205、V307、L103、X035、X315、H417。M030 と V407 は OEP の口から)。測定のスケッチはコアに入れず、計画のディレクトリか work/ に置く。

| ID | 測ること | 今わかっていること | 判断に効くこと |
|---|---|---|---|
| M1 | 消去と書き込みの単位と時間: 標準の消去、高速の消去、高速のページ書き込み、ページのバッファへの読み込み、2 バイト書き込み | 6 系列(flash-raw)。高速のページの消去・読み込み・書き込みを V006、V203、V205、V307、X315 で測った([measurements.ja.md](measurements.ja.md))。V407、M030、V00x の他品種は未測定 | 面の大きさ、commit の時間、止まる時間 |
| M2 | 処理中の CPU と割り込み、ほかの周辺の振る舞い: UART の受信(取りこぼし)、USB(切れるか)、PWM と DMA(続くか)、SysTick(数え続ける。E4 で確認済み) | 止まる系列: V003、V103、X035、L103、V006、V205。止まらない: V203、V307、H417。X315 ははっきりしない | commit 中に何を約束できるか。`millis()` の取り戻し |
| M3 | 消去後の値と、消さずに書き足せるか(高速のページ、2 バイト) | 0xFF で書き足せた: V003、V103、X035、L103、V006、V205。0xE339 で書き足せない: V203、V307、X315、H417。V407 は未測定 | 追記の形式(ログ、NVS 型)が使える系列 |
| M4 | 途中で止めたとき(リセット): 消去・書き込みのどの時点で、どんな中身が残るか | X035、V103、V003、V307、H417 | 形式の確かめ方(CRC の 2 回計算など) |
| M5 | 電源断(uhubctl で LinkE の口ごと切る): 1 回の消去・書き込みと、候補の形式の commit の途中で、各 30 回以上 | 生の消去・書き込みで V307、V003、V103 | 約束を文書に書けるか |
| M6 | 書き込みの経路ごとに末尾が残るか: ch32rv の各経路(stub、ローダー、OEP、HID、ISP、DFU)と `--erase` の値ごと | stub の `auto` は全体を消す(V307)。sector と DFU は残る。ほかは ch32rv のコードからの見立て(2026-10-28) | 書き込み直しで残す手段 |
| M7 | クロックを変えたときの時間(L103 の 8 / 96 MHz、V307 の 8 / 96 MHz など) | 未測定 | 時間の約束を F_CPU で変えるか |
| M8 | 起動時に領域を読む時間(候補の形式ごと、領域の大きさごと) | 未測定 | 起動を遅らせない大きさ |
| M9 | 書き換えの寿命の近くの振る舞い(1 ページを何万回か消して書く。1 個の石の 1 ページを犠牲にする) | データシートの最小値だけ | 数え上げの用途に何を勧めるか |
| M10 | 読み出し保護・書き込み保護とオプションバイトの、保存の領域への効き | 未測定 | 保護したい利用者への約束 |
| M11 | ほかの機能との重なり: 休止中の書き込みの禁止、WDT との時間、USB の接続中の commit | 未測定 | 休止の参加者・WDT の扱い |

## 4. 候補(同じ物差しで測る)

| 候補 | 形 | 想定する用途 |
|---|---|---|
| raw | 単位の問い合わせ、消去、書き込み(公開は決定済み) | 自分で形式を作る人 |
| 1 面の上書き | 消してから書く | 電源断を気にしない設定 |
| 2 面の入れ替え(EEPROM 型) | 新しい面に書いてから切り替える | 設定、校正値 |
| ページ内の追記ログ | 消去済みの上に書き足す(書き足せる系列だけ) | 数え上げ、小さな設定の頻繁な更新 |
| キーと値のログ(NVS / ZMS 型) | 複数ページを循環して追記し、古いものを回収 | 設定と数え上げの混在、名前付きの値 |
| ファイルシステム(LittleFS) | 内蔵フラッシュの上のファイル | 記録、大きな系列だけ |
| フラッシュ以外 | BKP、スタンバイで残る RAM、`.noinit` | 状態の続き |

物差し: 確保する大きさ、RAM、コードの大きさ(V003 で入るか)、commit の時間と止まる時間、電源断の約束、摩耗、書き込み直しで残せるか、12 ファミリーで同じ形を使えるか、使わなければ 0 B か、Arduino の定番の API との近さ、利用者が仕組みを説明できるか。

## 5. 進め方

1. 他の環境の調査を受け取り、1 の用途の表を埋め直す。
2. M1・M3 の未測定の系列を測る(V006、V203、V205、X315。OEP の口から M030、V407)。
3. M6 を実機で測る(ch32rv の各経路で、末尾に印を書いてから書き込み直す)。
4. M2 の周辺の振る舞い(UART の取りこぼし、PWM、DMA。USB は PC につながった X035 が無いので、V307 や L103 の USB で)。
5. M4 / M5 を、まず生の消去・書き込みで未測定の系列に広げ、候補の形式の試作ができたら commit の途中で行う。
6. M7、M8、M10、M11。M9 は最後に、捨ててよい石の 1 ページで。
7. 候補を物差しで並べた表を作り、全体の形・面の大きさの決め方・書き込み直しで残す手段を、選択肢と推奨にして相談する。

結果は、このディレクトリの `measurements.ja.md` に表で残す(生のログは work/)。測定のたびに、この計画の表の「今わかっていること」を更新する。
