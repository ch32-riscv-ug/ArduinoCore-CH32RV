# 常設ベンチの構成（案、2026-10-28）

[テスト構成の再設計案](TEST_DESIGN.ja.md)の常設ベンチを、**今の機材にとらわれず、あるべき形**として書いたものです。環境は全体を入れ替える前提です。今の手持ちは付録 A に残しました。

根拠は次のとおりです。
- 型番ごとの機能: ch32-device-data の parts.csv（各データシートの型番比較表から取った値）。
- コアの対応範囲: boards.txt（27 系列、105 型番、製品ボード 1）、周辺機能表（docs/peripheral-support.ja.md）、USB の一覧（docs/usb.ja.md）。

## 1. 選び方

- **ファミリーごとに 1 台、そのファミリーで一番機能の多い型番を OEP につなぐ**（基本の 12 台）。コアの分岐を実機で一番多く通るため。
- **型番で分岐するコアのコードがあるものは、その型番も実機で持つ**（境界の DUT）。系列の中で、型番によって有無の変わる機能（Ethernet など）が対象。
- **型番の違いが容量・端子の数だけのものは、ビルドで確かめる**（CI の全構成ビルド）。実機は持たない。
- **製品ボードは常設**にする。ファミリーの DUT と OEP を共有してよい。
- **基板は、全端子が出ている評価ボード**（WCH の EVT ボードなど）を選ぶ。配線を多くとるため。

## 3. 境界の DUT（型番で分岐するコード）

| 型番 | 実機で確かめること | 理由 |
|---|---|---|
| **CH32V203RBT6** | Ethernet（V20x の中で、この型番だけ） | コアは `CH32RV_PART_CH32V203RBT6` で Ethernet を分けている。CPU Clock にも「60MHz (Ethernet on V203RB)」がある。データシートは型番の表（CH32V203DS0）にだけ「10M」と書き、系列の比較図には書いていない |
| CH32V317WCU6 または VCT6 | 10/100M の Ethernet | V307（10M の PHY）と別のドライバの経路（`ETH_V317`） |
| CH32V002F4P6 など | 4 KB の RAM で、V00x の小さい側 | V003 の 2 KB と別の linker の設定。ビルドで足りるなら実機は不要 |

ビルドだけで確かめるもの: V004 / V005 / M007、M103、X033、X305（SPI1 が無い）、H415 / H416（Ethernet・SS が無い）、V303（USBHS が無い）、V467、V407RET6。

## 5. OEP の割り当てと配線

### 1 台の DUT に引く線（標準）

| 線 | 本数 | ラベル |
|---|---|---|
| デバッグ | 1〜2 | `swio`、または `swdio` / `swclk` |
| リセット | 1 | `nrst` |
| 電源の入り切り | 1 | `power_hi` など（今の名前） |
| コンソールの UART | 2 | `rx` / `tx` |
| 周辺 | 10 前後 | DUT の端子名（`pa10` など）。GPIO の入出力 2、2 本目の UART 2、I2C 2、SPI 4、PWM 1、ADC 1 |

1 台でおよそ 16 本です。I2C のプルアップは、切り替えられる形で基板の側に置きます。

### P4 の割り当て（案）

| P4 | DUT | 理由 |
|---|---|---|
| 専用 ×6 | V307、V407、H417、V205、X315、V208 | 端子が多く、2 本目以降の UART・SPI などまで配線したい |
| 共有 A | V003、V00x、UIAPduino | ピンが少ない。口が複数の構成を普段から通す |
| 共有 B | V103、L103 | 同上 |
| 共有 C | M030、X035、WeAct X035 | 同上 |
| 境界用 | V203RBT6、V317 | Ethernet だけが目的なので、配線は少なくてよい。共有でよい |

合計で P4 が 9〜10 台です。**P4 1 台で使える端子の本数は未確認**です（ファームの宣言と予約の端子を数える）。共有 1 台に 3 台の DUT（48 本）が載るかは、その数で決まります。

## 6. エコシステム（書き込み・起動・更新）

OEP の常設とは別の、小さな組にします。

| 経路 | DUT | 要るもの |
|---|---|---|
| WCH-LinkE（ファーム 2.22） | V307、X035 など 2〜3 台 | LinkE、UART を Link に配線 |
| WCH-LinkE（ファーム 2.12） | 1 台 | 版の違いを見るため |
| WCH-Link（CH549） | 1 台 | 古い Link の挙動（約 16 バイト単位の受け渡し） |
| USB の ISP | X035、L103 など | BOOT と RESET を操作する手段（P4 の GPIO で補助してよいが、書き込みは P4 で代行しない） |
| USB DFU | H417 | SS を挿したまま書き込む経路 |
| 製品の HID | UIAPduino | — |

## 7. 相手と設備

| 構成 | 要るもの |
|---|---|
| USB device | 電源を個別に切れる USB ハブ（uhubctl）で、各 DUT の USB を PC へ |
| USB host | ESP32-S3（device の相手）を、host を持つ DUT ごとに。device の相手と host の相手で計 2 台以上 |
| USB HS / SS | HS / SS のハブとケーブル。PC のポート |
| Ethernet | スイッチと DHCP のある LAN。相手の PC |
| PD | PD 電源（ソース）と PD シンク。VBUS の電圧計 |
| ADC / DAC | 安定した電圧源と DMM（または OEP のアナログ取り込みで代える） |
| I2C / SPI の相手 | OEP のファームが I2C target / SPI slave を持つか確かめる。無ければ ESP32 などの peer |

## 8. 決めること

1. **確保する DUT**: V208WBU6（または RBT6）、V203RBT6、M030C8T7 / C8U7。V317 は Ethernet をどこまで見るかで決める。
2. **P4 1 台で使える端子の本数**を数え、共有の組み方を決める。
3. **評価ボードの選定**: 全端子が出ているか、USB・RJ45・CC が出ているか、電源を外から切れるか。
4. **I2C / SPI の相手**を OEP が受け持てるか。
5. **コアの型番の扱い**: V208CBU6 には Ethernet が無いが、コアは V208 の全型番で Network をビルドする（lwipopts.h が系列で判定）。型番で断るように直すかを決める。

### A.5 このときの漏れ

1. **OEP への移し替え**: 1 章の 9 台を、どの P4 のどの口にするか。共有と専用の分け方（TEST_DESIGN 5 章）。RP2040 とネットワークの ESP32 の割り当て。
2. **足りない DUT**: Ethernet を持つ V20x（V208 か V203RBT6）。
3. **見えていない機材**: WeAct の X035（P4 30eda0e34a0e）、V003 の治具。
4. **型番の差を実機で見るか**: V00x の 6 系列、M103、X305、H415 / H416、V303、V467。ビルドだけで足りるもの・実機が要るものを分ける（例: 容量の端は V002、拒否の動きは V303）。
5. **PD、ADC / DAC の基準、I2C / SPI の相手**の機材。
6. **LinkE の UART の配線**: V205 と X315 は、UART が Link につながっていない。エコシステム側でコンソールを UART にするなら配線が要る。
