# 常設ベンチの構成（案、2026-10-28）

[テスト構成の再設計案](TEST_DESIGN.ja.md)の常設ベンチを、**今の機材にとらわれず、あるべき形**として書いたものです。環境は全体を入れ替える前提です。今の手持ちは付録 A に残しました。

根拠は次のとおりです。
- 型番ごとの機能: ch32-device-data の parts.csv（各データシートの型番比較表から取った値）。
- コアの対応範囲: boards.txt（27 系列、105 型番、製品ボード 1）、周辺機能表（docs/peripheral-support.ja.md）、USB の一覧（docs/usb.ja.md）。

## 1. 選び方

- **ファミリーごとに 1 台、そのファミリーで一番機能の多い型番を OEP につなぐ**（基本の 12 台）。コアの分岐を実機で一番多く通るため。
- **型番で分岐するコアのコードがあるものは、その型番も実機で持つ**（境界の DUT）。系列の中で、型番によって有無の変わる機能（Ethernet など）が対象。
- **型番の違いが容量・端子の数だけのものは、ビルドで確かめる**（CI の全構成ビルド）。実機は持たない。
- **製品ボードは常設**にする。ファミリーの DUT と OEP を共有してよい。
- **基板は、全端子が出ている評価ボード**（WCH の EVT ボードなど）を選ぶ。配線を多くとるため。

## 3. 境界の DUT（型番で分岐するコード）

| 型番 | 実機で確かめること | 理由 |
|---|---|---|
| **CH32V203RBT6** | 基本の V20x と兼ねる（2 章） | コアは `CH32RV_PART_CH32V203RBT6` で Ethernet を分けている。CPU Clock にも「60MHz (Ethernet on V203RB)」がある。データシートは型番の表（CH32V203DS0）にだけ「10M」と書き、系列の比較図には書いていない |
| CH32V317WCU6 または VCT6 | 10/100M の Ethernet | V307（10M の PHY）と別のドライバの経路（`ETH_V317`） |
| CH32V002F4P6 など | 4 KB の RAM で、V00x の小さい側 | V003 の 2 KB と別の linker の設定。ビルドで足りるなら実機は不要 |

ビルドだけで確かめるもの: V004 / V005 / M007、M103、X033、X305（SPI1 が無い）、H415 / H416（Ethernet・SS が無い）、V303（USBHS が無い）、V467、V407RET6。

## 3.1 今の開発ボードで足りるか（端子の取り合い、2026-10-28）

型番の端子だけで判定した結果です（pinout.csv。デバッグ・USB・水晶の端子とぶつからない route があるかを、I2C・SPI・USART のインスタンスごとに見た）。基板の上の部品は見ていません。

| ボード | 結果 |
|---|---|
| V003、V006、V103、V205、V307、V407、L103、X035C8T6、X315、H417 | I2C・SPI・USART のどのインスタンスにも、空いた route がある |
| X035F8U6（WeAct） | **I2C は試せない**。route が USB（PC16 / 17）か、2 線のデバッグ（PC18 / 19）にしか無い。USART1 は無く、USART3 はデバッグとぶつかる。I2C は C8T6 で確かめるので追加は要らない |
| M030G8R7 | **SPI が無い**。I2C1 と USART1 は、どちらも PB6（水晶の端子）を通る route だけが使える（デバッグは 1 線なので PA2 は空く）。基板に水晶が無いことが条件で、I2C と UART のコンソールは同時に配線できない（コンソールを DMSEQ にすれば I2C に回せる） |
| V20x | Ethernet は V203RBT6（または Ethernet 付きの V208） |

**確保が要るもの**: V203RBT6（予定どおり）。M030 の SPI を実機で見るなら、K8U7 / C8T7 の変換基板（公式ボードを待つなら不要）。

**回路図で確かめること**: 上の route の端子に基板の部品が載っていないか。X035C8T6 の基板に CC の端子があるか（PD）。V307 / V205 の基板に HSE の水晶があるか（USBHS）。X315MCU6 の基板に SS のコネクタがあるか。V407 の基板に USB の口が 2 つあるか。

## 5. OEP の割り当てと配線

### 1 台の DUT に引く線（標準）

| 線 | 本数 | ラベル |
|---|---|---|
| デバッグ | 1〜2 | `swio`、または `swdio` / `swclk` |
| リセット | 1 | `nrst` |
| 電源の入り切り | 1 | `power_hi` など（今の名前） |
| コンソールの UART | 2 | `rx` / `tx` |
| 周辺 | 10 前後 | DUT の端子名（`pa10` など）。GPIO の入出力 2、2 本目の UART 2、I2C 2、SPI 4、PWM 1、ADC 1 |

1 台でおよそ 16 本です。I2C のプルアップは、切り替えられる形で基板の側に置きます。

### P4 の割り当て

- P4 は十分な台数を用意するので、**分け方は配線をしながら決める**。
- 配線の本数から見て、**1 台の P4 に載せる DUT は 2 台まで**を目安にする（1 台で約 16 本）。
- 端子の多いファミリー（V307、V407、H417、V205、X315、V20x）は 1 台ずつ。
- 口が複数の構成を普段から通すため、**2 台を載せる P4 を少なくとも 1 台**は常設にする（ピンの少ない V003・V00x・M030・製品ボードから組む）。

## 7. 相手と設備

**常設ベンチは配線を固定し、相手は基本マイコンにする。** PC を相手にする確認（OS のドライバ、ISP の書き込みの往復など）は常設の外に置く。USB の相手のマイコンの扱いは、TODO の「USB デバイスの実機試験のホスト役を PC から別のマイコンに替える」で決めたとおり。

- 相手のマイコンも OEP から SWD で書き込み、試験の指示と結果は OEP 経由でやり取りする。
- 相手の USB の口は、DUT の相手専用にする。
- VBUS は流さず、DUT も相手も 3V3 で動かす。
- 抜き差しは、DUT の `end()` → `begin()` と、相手側のポートのリセットで代える。サスペンドは相手が SOF を止めて起こす。

| DUT の口 | 持っている DUT | 相手 |
|---|---|---|
| RJ45（Ethernet） | V203RBT6（または V208）、V307、V407、H417 | スイッチと DHCP、相手のマイコン（Ethernet を持つ別の DUT）か常設の PC |
| USB FS | V103、V20x、V205、V307、L103、M030、X035、H417 | **常設の標準ベンチは全部 Pico**（host と device の相手。arduino-pico の Adafruit TinyUSB で相手の sketch を作る）。**X035 を 1 台だけ ESP32-S3 と組にする**（今の usb-peer の試験と EspUsbHost / EspUsbDevice をそのまま使い、ESP32 の USB スタックとの相互運用を 1 組確かめる） |
| USB HS | V205、V307、V407（2 口）、X315 | **常設で試すかは未定**（相手の P4 が DUT ごとに要り、台数が多くなるため省く可能性がある）。試すなら **ESP32-P4**（OEP とは別の個体。EspUsbHost / EspUsbDevice が P4 の HS で host と device の両方に対応）。**H417 の HS は常設では試さない**（SWD と端子を共用していて検証が難しいので、手作業の試験だけ） |
| USB SS | H417、X315 | **H417 どうし**（H417 は 2 台を追加で確保中、計 3 台）。DUT が device なら相手の H417 が SS の host、DUT が host なら相手の H417 が SS の device。X315 の SS は device だけ（相手は H417 の host）。SS の host を作る間は、市販の USB 3.0 のメモリで手作業の試験をし、安定したら H417 どうしのピア試験に移る |
| USB-C の CC（PD） | X035（常設に置くかは未定） | PD は基本は手作業の試験。常設に置くなら **X035 どうし**で、片方の CC の抵抗（WeAct の基板の R4 / R5）を外してソースにし、シンクとソースのピア試験にする。L103 / V205 / X315 / H417 / M030 の PD は手作業 |

- **コアの USBSS の host を実装する**（H417。今は device だけ）。これが無いと、SS の試験は相手を用意できない。
- H417 の USB の HS の線を切り離す部品を確保中。HS を切り離せば SWD（PB8 / PB9 は USBHS と共用）で書き換えられるので、SS の口を挿したままでも DFU に頼らずに済む。
- 電源の入り切りは OEP からのリセット（NRST / デバッグ線）で代え、常設には電源のスイッチを足さない。
- ADC / DAC の絶対値は、OEP の `oep.fixture.analog` で足りるか確かめ、足りなければ電圧源と DMM。

## 8. 決めること

1. **確保する DUT**: V203RBT6（V20x を V208 から入れ替える）。M030 は公式ボードが出たら C8T7 / C8U7 へ。V317 は Ethernet をどこまで見るかで決める。
2. **P4 の分け方**は配線をしながら決める（1 台に 2 台まで）。
3. **LinkE 2.12 を残すか**（上げてしまうと版の違いを確かめる手段が無くなる）。
4. **評価ボードの選定**: 全端子が出ているか、USB・RJ45・CC が出ているか、電源を外から切れるか。
5. **USB の相手**: Pico 用の相手の sketch（Adafruit TinyUSB の device と host）を作る。SS の相手に 2 枚目の H417 を用意し、コアの USBSS の host を実装する。
6. **OEP の I2C / SPI の controller**: OEP セッションに追加を依頼した（主側と従側の両方を OEP で受け持つ）。できるまで、DUT が従になる試験は保留。
7. **コアの型番の扱い**: V208CBU6 には Ethernet が無いが、コアは V208 の全型番で Network をビルドする（lwipopts.h が系列で判定）。型番で断るように直すかを決める。

4. **型番の差を実機で見るか**: V00x の 6 系列、M103、X305、H415 / H416、V303、V467。ビルドだけで足りるもの・実機が要るものを分ける（例: 容量の端は V002、拒否の動きは V303）。
5. **PD、ADC / DAC の基準、I2C / SPI の相手**の機材。
6. **LinkE の UART の配線**: V205 と X315 は、UART が Link につながっていない。エコシステム側でコンソールを UART にするなら配線が要る。
